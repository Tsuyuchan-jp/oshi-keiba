# 要件ロードマップ

① が着手中。②〜⑦ は未着手。

## ① 投票・オッズ設計（着手中）

- 参考オッズ（Seed×w+Real）と確定配当（実票のみ）。w と目安額は管理者 UI
- 投票締切はゲーム内で着順が見える前（日時＋強制ボタン）。清算は note 公開に合わせる（締切とは別）
- 週次: スクショで出走登録を先に締め、アプリで Seed。投票開始と部屋立ての前後は Neko さん相談で未決
- ポイントは蓄積。1頭全額可。1人一票にしない
- 賭式: MVP は単勝。内部は賭式非依存
- 初期シード V = 作者評価モデル（[04-strength-model.md](04-strength-model.md)）。Strength 混ぜは B

④のうち「毎週の配布量」は実質①の一部。

## ② 結果確定・清算フロー

- 手動の着順入力・確定
- note 公開と結果公開の同期（ネタバレ防止）
- パリミュチュエル清算（控除率など）
- 出走取消時の返還（事前あり・ゲーム内なしは実競馬と同様）
- 飛び入り発生時は要検討（ゲーム内の再部屋・再出走が分かりやすい案）

- 誰が何に賭けたか、コメント、キャラ付け、週次リキャップなど
- 投票期間の長さは、開始時刻（部屋の前か後か）次第。開始は Neko さん相談待ち

- 景品の中身は Neko長明さんと後相談でよい

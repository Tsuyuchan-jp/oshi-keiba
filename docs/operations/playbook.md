## 流れ

1. `setup`: 本戦頭を登録。評価点（OCR または直置き）。賭式・S・E・締切
2. 投票開始 → `voting`。メンバーは `/bet` でその開催に参加してから買う（参加で G）
3. 日時または強制締切 → `closed`: 確定配当のみ。着順は出さない。賭式ごとに成立／特払い予定
4. 着順保存のあと公開 → `published`: 払戻。着順と自分の的中／特払い／取消
5. 「次の開催を開く」→ 新しい `setup`。前の開催は残る

文言: `setup` 出走登録中 / `voting` 投票中 / `closed` 投票締切（確定配当） / `published` 結果公開

自分の購入内容は `/tickets` の疑似馬券で確認する。場内・窓口・パドックの3点リーダから常時開ける。窓口には購入枚数と合計からの導線、結果公開後の場内は結果の盤で上部、全頭表示で一覧下部に的中有無を知らせる大きな導線を出す。場内には馬券明細の小さな一覧を置かない。状態ごとの表示と集約ルールは [tickets.md](../features/tickets.md) を正とする。

### 投票ページ（窓口）

- 未参加の投票中は、買うUIを出さず「（開催名）に参加する」だけ。参加後は買う
- 賭式切替。初期は単勝。無効な賭式は薄く出して押せない。1点買い
- 買いUIはマークカード（チップタップ。枠ウェルで解除）。セレクトは使わない
- パドックから候補を引き継いだ場合は1枠目へ事前選択し、候補表示と解除リンクを出す
- 馬連・3連複は順不同（内部でソート）
- 連勝オッズは投票中の参考オッズ、締切後の確定配当として表示する。未成立・未計算の買い目は「—」
- 金額は `+100 / +500 / +1,000` で加算し、「全額を入力」で購入可能な最大額、「リセット」で 0 を入れる。金額ボタンはスマホで押しやすい44px以上の高さ
- スマホの購入欄は、必要な頭数をすべて選び終えるまで「金額」と「買う」だけのコンパクト表示にする。選択完了後に、金額の増額・全額・リセット・案内を展開する
- 三連複・三連単の選択枠は、選択前から `5rem` の固定高にする。ウマ娘名は省略せず、折り返して全文を表示する
- 馬番一覧は前半を左列、後半を右列に並べる。奇数頭では左列を1件多くする
- PC（900px以上）は窓口枠を `100dvh - 3rem` の高さに固定する。ヘッダー・所持スペ・購入欄を残し、馬番一覧などの本文だけを枠内でスクロールする
- 「買う」は管理者プレビュー以外では押せる状態にする。不足している買い目・金額・残高は画面内と押下時に案内し、条件が揃ったときだけ確認ダイアログへ進む
- 自分の票だけ。やりなおしは文字リンク
- 確認: 「全ての馬券がリセットされますがよろしいですか？」

### パドック

- ログイン済みのメンバーと管理者が閲覧できる。投票期間外も見られる
- 出走ウマ娘を逃げ・先行・差し・追込で分けて表示する。脚質未設定の頭は表示しない
- 詳細はウマ娘名・出走者・参考オッズ・意気込み・スキルパワー・基礎能力・適性。保存済みの場合だけ育成スクリーンショットとトレーナーアイコンを表示する
- 育成スクリーンショットはモーダルで表示し、クリック／タップで初期表示の2.2倍へ拡大できる。拡大後はスクロールで確認し、スマホでは閉じるボタンを右上に固定する
- スマホは画面高に合わせて脚質ごとの行間と画像高を縮め、最大18頭でもページ全体をスクロールさせずに表示する。横方向の並びは縮めない
- スマホの詳細カードは下部に格納できる。閉じたカードの見出しはタップまたは上スワイプで開き、開いたカードは見出しから、または本文が最上部のときに下スワイプで閉じる。本文を読んでいる途中の縦スクロールは維持する
- 「このウマ娘を投票候補にする」で `/bet?candidate=` へ遷移し、投票中・参加済みなら窓口の1枠目に入る。参加前は参加後にも引き継ぐ。候補は窓口から外せる

## 入場

`/login` 1枚・2ボタン。個人パスワードなし。なりすまし耐性は捨てる。見出しは入場。URL はそのまま。

- 初めて: 未登録なら口座作成。同名ありは拒否。G は入らない

## 賭式と払い

各賭式は別プール。当選キーは常に1つ。複勝・ワイドは当たりが複数なので後回し。

**①**: 確定は実票だけの山分け。Seed は投票中の参考にだけ混ぜる。

**特払い B**: 当たりの組み合わせに実票ゼロのとき、その賭式に賭けた人全員へ控除後を戻す（100 → 80、端数切り捨て）。全額返還ではない。

出走取消は別。そのウマ娘を含む票は全額戻す。

## 管理

- 開催設定はモックの箱。`name` と POST は従来どおり。投票中に保存できるのはタイトル・未来の締切・S・E・w時・Dだけ。賭式・参加G・単位・レギュレーション・スキル重みは投票開始後に固定する。D は 0〜0.99（モックの％にはしない）
- 賭式のオンオフは setup だけ
- 出走の登録名はウマ娘名と出走者を分ける（OCR はウマ娘名へ。詳細は [ocr.md](../specifications/ocr.md)）。スキル辞書をゲーム更新へ追従したあとは、対象開催のイベント設定を保存し直して有効スキル一覧を取得し直す。保存前のスナップショットには新規スキルの有効判定が入らない

- ウマ柱タブは `/admin/umabashira`（ラベル「ウマ柱」、ナビは開催設定の下）。正は管理タブとメンバー向け場内モーダルで共有する紙面（枠色は見た目専用。ノイズ 0.1。出走登録中も参考オッズ。評価点・SP点数の色箱は PNG を正）。仕様は [umabashira.md](../features/umabashira.md)。ログイン済みメンバーは場内の⋯から閲覧でき、出走登録中と投票中は足元の「ウマ柱を見る」も残す。締切中の足元には出さない。スマホは全画面・ピンチ操作、PCはホイール拡大とドラッグ移動。管理者が配る形式は PNG と WebP
- 管理の見た目はダッシュ（IBM Plex CDN）。逃げは開閉レール。着順は案3。内部計算はオッズのモーダル。スタミナ目標値は脚質別8項目を開催設定のモーダルで入力する。電光は移さない
- **本番デプロイ**は [release.md](release.md) の手順を通す。R2 作成と D1 `--remote` を `deploy` の前にやり、公開直後の確認と障害時の判断も同手順に従う
- **アプリ版**: 履歴と上げ方は [version.md](version.md)。数字の正本は `package.json`（画面は `v` 付き）。ウマ柱のメンバー閲覧は実機確認を完了（2026-09-12）
- デモ初期化: 本番では出さない。ローカルは `npm run dev` が `ALLOW_DEMO_RESET=1` を渡す。表示名は残す。開催・票を消し残高は 0。G は配らない
- 締切を投票中に戻す（実装クローズ。ローカル実機確認OK。2026-09-24）: 同じローカル限定。締切（`closed`）だけを、出走と馬券を残して投票中へ戻す。着順と締切時の分析ログは消す。過ぎた締切時刻は未設定にする。結果公開後は戻さない。登録まで戻すときは、その後の「投票を取り消して登録に戻す」を使う
- 汎用Undoは廃止した。公開前の着順は正しい内容で再保存して訂正する。公開・払戻後に誤りが判明した場合は、自動復旧せず個別に復旧方法を判断する
- 投票開始は、締切が未来・出走2〜18頭・開催設定（コース／条件／評価目標／脚質別スタミナ8項目）・スタミナ勝負・余剰スタミナ評価の明示選択を満たしてから行う。開始前モーダルで開催設定と出走登録一覧を目視確認し、「この内容で投票を開始」を押す。条件不足時は開始できない
- 運営の事前評価は出走登録タブ右上のモーダルで記録する。全頭を開き、順位・メモは必要な頭だけ入力する。投票開始時に入力内容と評価式の版を固定し、投票開始後は出走タブで閲覧する。投票開始を取り消して登録へ戻した場合は固定記録も解除され、再編集できる
- 分析ログタブは未退避容量、R2退避回数、退避失敗、容量保護による省略件数を表示する。通常は操作不要。3MiBで自動退避し、失敗時はD1を残す。4MiB警告が出ても投票は続行し、終了後に「分析データを一括ダウンロード」を行う
- 投票開始後はメンバー削除を普段押さない。メンバー利用停止には管理者パスの再入力が必要
- 「次の開催を開く」は結果公開のあと。誤って開いた setup は「この開催を破棄」（管理者パス＋確認）
- 投票開始が早いときは「投票を取り消して登録に戻す」（票は全額戻し、その開催の G も戻す。管理者パス＋確認）
- 出走クリア・開催破棄・投票の登録戻しは、いずれもモーダルで管理者パスと確認ダイアログ
- 締切日時は開始ボタンと別フォーム。保存してから開始する。未設定または過去日時では投票を開始できない

3. 本戦頭の評価点（OCR 材料から自動。足りなければ直置き）。評価式を更新した開催では、出走タブで再計算の差分を確認して確定
4. 余力に応じて、出走登録タブの「運営の事前評価」に順位・メモを残す
5. 「投票開始」を押し、開始前モーダルの設定・出走登録一覧を目視確認してから開始
6. URL と共有パスを閉じた経路で渡す。メンバーは投票ページで参加してから買う
7. 着順が見える前に締切
8. note に合わせて着順入力 → 結果公開して払戻
9. イベント終了後、管理の分析ログタブで退避失敗・省略件数を確認し、「分析データを一括ダウンロード」を1回実行

飛び入りはアプリに足さない。

## 許容するリスク

- 表示名を知っていれば他人の口座に入れる
- やりなおしで板が揺れる
- 連勝は票が薄く、高配当か特払いになりやすい

## 連勝への Seed（後付けメモ）

参考にだけ足すなら確定は触らない。開場・実票ゼロのパリミュチュエルはだいたい `0.8 × 買い目の数`。連勝参考オッズは評価点の γ 乗で確率を作り、現在の γ は2。第2回は評価点70未満を70として扱う暫定措置を入れている。低評価を含む買い目の倍率と、表示上限9999.9倍への張り付き状況を開催後に確認し、70を再検討する。

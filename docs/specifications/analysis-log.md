# 分析ログ

**いまの段階:** 連勝情報・容量保護まで実装済み（2026-09-23）。本番適用後、第2回終了時に一括ダウンロードして検証する。

連勝は、各賭式の計算条件、実票のある全買い目、各賭式の人気上位10件を保存する。窓口で最後の1頭を選ぶ途中に出す候補一覧は、同じ時点の板から再計算でき、個人操作にも近いため保存しない。

第2回以降の投票中ボードを、次開催のオッズ調整に使うための仕様。数式そのものの正本は [odds.md](odds.md)。開催ごとの分析結果は [`reports/`](../../reports/) に置く。

第2回は、連勝参考オッズの評価点下限70を暫定適用する。これは連勝参考オッズだけの値で、表示評価点・単勝・確定配当には適用しない。開催後のレポートでは、70未満の頭数、下限適用前後の人気上位・中央値・高倍率帯、表示上限9999.9倍への到達件数、メンバーの反応を記録し、次回の維持・変更・撤廃を判断する。

## 目的

第3回以降に S / E / D / w時下限 / 指数 / λ を調整するとき、次を事実にもとづいて比較できるようにする。

- 一投票による参考オッズの変動幅
- TV と w時・w票・合成 w の進み方
- 締切直前の参考オッズと確定配当の差
- 連勝のSeed・参考オッズと、実際に票が入った買い目の関係
- 人気上位・中穴・大穴の倍率感と、`γ=2`・評価点下限70の妥当性
- 参加者数・投票者数・有効馬券数と実票額の関係

これはメンバー向けの機能ではない。管理者だけが `/admin/analysis` から閲覧・出力する。

## 記録するタイミング

投票中に、次の時点でメンバー画面に見えていた板を自動記録する。

- 投票開始直後
- 投票確定の直後
- やり直しの直後
- 出走取消の直後
- 締切直前（強制締切・時刻による自動締切の直前。参考オッズ）
- 締切後（同じ締切処理の直後。確定配当）

時間の経過だけによる板の連続記録は行わない。`w時` の調整を詳しく検討する必要が生じたときだけ、別途その開催向けの観測方法を決める。締切直前と締切後は同じ時刻を使うため、参考オッズと確定配当を正確に比較できる。

## CSV一式の契約

「分析データを一括ダウンロード」は以下の5ファイルをZIPで返す。数値は分析用の生値を保存し、画面だけが表示用に丸める。日時は `captured_at_jst` の `+09:00` を正とする。

| ファイル | 1行の意味 | 主な項目 |
|---|---|---|
| `snapshots.csv` | 1回の板の記録 | 時刻、記録理由、S/E/D/w時下限/指数/λ、w時/w票/w、TV、人数・件数 |
| `markets.csv` | 1回の記録における連勝1賭式 | 賭式別実票、E、S、γ、評価点下限、w時・w票・w |
| `odds.csv` | 1回の板に出た1行の買い目 | 賭式、買い目、実票、参考オッズ／確定配当、Seed、Display、実票あり、人気順位 |
| `horses.csv` | その開催の出走対応表 | 馬ID、馬番、表示名、評価点、取消、着順 |
| `analysis-status.csv` | 一括出力時の保存状態 | 3MiB・4MiB閾値、退避回数、省略件数、退避失敗 |

`odds.csv` の単勝は出走中の全頭を保存する。連勝は、各賭式の参考オッズ人気上位10件と、実票が入っている全買い目の和集合を保存し、重複させない。`popular_rank` は1〜10、`is_bet=1` は実票ありを表す。締切後は実票だけで確定配当を計算するため、実票のある全買い目が対象になる。

`bettor_count` は一度でも投票した人数、`active_bet_count` はその時点で返還されていない馬券件数、`joined_count` は開催へ参加済みの人数である。単に `n` と書かない。

個別の投票者名・残高・個人ごとの投票内容は分析CSVに含めない。必要なら管理の台帳を使う。

## 容量保護とR2退避

容量は開催ごとの未退避CSVデータをUTF-8・未圧縮バイト数で増分計測する。投票のたびに過去ログ全体を読み直さない。

- **3 MiB:** 管理の分析ログタブに状態を出し、その時点までの完成済みログを非公開R2へZIPで自動退避する。
- R2保存に成功した後だけ、退避済みの元データをD1から削除する。R2失敗時はD1を削除せず、エラーを分析ログタブに出す。
- **4 MiB:** 退避失敗が続いた場合の安全弁。投票・やり直し・取消による通常スナップショットを一時停止する。投票処理そのものは続ける。
- 投票開始、締切直前、締切後の記録は予約枠として4MiB到達後も保存する。
- 省略件数と退避失敗は管理画面と `analysis-status.csv` に残す。分析時は必ず確認する。

同時投票では容量をD1上で原子的に加算する。退避処理は開催ごとに1件だけが実行し、退避開始後に完成した新しいスナップショットを削除対象へ混ぜない。処理が中断した場合は5分後から再試行できる。

自動退避がある開催の一括ZIPには `part-001.zip`、`part-002.zip` のような退避分、最新の `part-current.zip`、`analysis-status.csv`、説明用READMEが入る。開催後は管理者が一括ZIPを1回ダウンロードすればよい。各Partも分析ログタブから個別取得できる。

## 開催設定の固定

原則として S / E / D / w時下限 / 指数 / λ は、**投票開始後に変更しない**。これらは開催中のメンバー表示と分析結果の前提になるためである。

例外的に変更する必要がある場合は、変更時刻・変更前後の値・理由を開催レポートへ残し、後述の `formula_version` を更新する。

## 数式・表示を変えるときの確認

次のいずれかを変更する作業では、実装前にこのページを確認し、ログ・CSV・テストを同じ変更に追従させる。

- 参考オッズ、確定配当、Seed、Imputed、TV、w時、w票、w の計算
- S / E / D / w時下限 / 指数 / λ の意味・入力範囲・初期値
- メンバーへ表示する賭式・買い目・オッズの丸め方
- 投票、やり直し、返還、取消、締切の状態遷移
- 分析CSVの列・値の意味

確認項目は次のとおり。

1. 変更前後で、どの板の値が変わるかを [odds.md](odds.md) に書く。
2. スナップショットが必要な入力値・中間値・表示値を残せるか確認する。
3. CSVの既存列を削除・改名・別の意味にしない。必要なら列を追加する。
4. Worker結合テストで、記録タイミング・CSV内容・過去開催の出力を確認する。
5. 実際の開催後、AIへ渡すレポート用の指示と比較表を `reports/YYYY-MM-DD/` に残す。

## バージョン

式の意味が変わると、同じ列名でも開催間の比較が誤解を招く。計算式・λの扱い・表示対象・控除計算を変更する場合は `formula_version`（例: `odds-v2`）を上げる。SやEの**値だけ**を変える場合は上げない。

分析CSVには `formula_version` と `schema_version` を保存する。連勝Seed・参考オッズ・人気順位・容量状態を追加した現在値は、それぞれ **`odds-v3`** と **`analysis-log-v2`** である。第2回より前の `odds-v2` / `analysis-log-v1` と比較するときは同じ形式として混ぜない。

分析ログの保存失敗は投票の成立を妨げない。失敗は管理の分析ログタブに件数と直近時刻を出し、D1へ失敗履歴を残す。D1自体が利用不能で履歴も残せない場合はWorkerログへ記録する。

「投票を取り消して登録に戻す」では、その開催のスナップショット・オッズ明細・ログ保存失敗履歴も消す。この操作を戻す汎用Undoは提供しない。

## 開催後の使い方

1. 管理の「分析ログ」から対象開催の「分析データを一括ダウンロード」を押す。
2. `analysis-status.csv` で退避失敗・省略件数が0か確認する。分割ZIPがある場合はすべて展開する。
3. AIにCSVを渡し、オッズ推移、TV・w推移、連勝の人気帯、締切前後の比較、投票1回あたりの変動幅をHTMLレポートにするよう依頼する。
4. CSVそのものと生成した Markdown / HTML を `reports/YYYY-MM-DD/` へ保存する。
5. 評価点下限70と `γ=2` の維持・変更・撤廃を含め、次開催の仮値・採否・判断理由を開催レポートに記録する。

# 確定配当に Seed を残す（作業仕様）

**用途:** 第3回メンバーシップ特別レースで、確定配当と払戻に Seed を含める実装だけに使う。チャットで決めた内容の控えであり、この作業中の正はここである。恒久仕様は [odds.md](odds.md)・[analysis-log.md](analysis-log.md)・[playbook.md](../operations/playbook.md) にあり、実装完了時に必要な確定事項だけをそちらへ移す。移し終えたら、このファイルは削除またはアーカイブする。

**やらないこと:** 実装完了前に、このファイルの内容を恒久仕様へ混ぜない。分析ログの成形、複勝の追加、パドックの改修は別作業である。

## 決まったこと

第2回までの約束（確定・払いは実票のみ。Seed 込みでは払わない）をやめる。投票中のオッズと締切後の確定配当は同じ計算にする。払戻がメンバーの投票額を超えてもよい。

- 指数 `γ` は `2` のまま
- 評価点の下限 70 は撤廃する。連勝の確率に使わない
- 当たる買い目の倍率に上限は置かない。払戻の計算にも、画面の `9999.9+` にも掛けない
- 買い目ごとの最低 Seed は置かない
- 控除 D は残す。開催設定の値を、投票中も確定も払戻も同じ率で使う
- 単勝の仮想票は評価点の比。`γ` は掛けない
- 連勝の仮想票は、いまの参考オッズと同じ確率（`γ=2`、着順どおり。馬連・3連複は成立する順番の合計）
- `w`（時間と票量）と `E` は削除する。時間が過ぎただけではオッズは動かない
- 単勝の Imputed（連勝の実票を単勝へ割り振ること）は削除する。連勝の実票は単勝オッズを動かさない
- 特払い B は、この式の開催では出さない。試しの方針であり、恒久化するかは開催後に見る
- 出走取消と投票のやり直しは、今どおり全額返還する。特払いではない

### 式

出走取消の頭は、今どおり Seed の配分から外す。評価点が 0 の頭の Seed は 0 である。

単勝:

```
Seed_i = S_単勝 × 評価点_i / Σ 評価点
持ち分_i = Seed_i + その馬の単勝実票
プール = S_単勝 + 単勝の実票合計
オッズ_i = プール × (1 − D) / 持ち分_i
```

連勝（馬連・馬単・3連複・3連単）:

```
q_i = 評価点_i^γ / Σ 評価点^γ     γ = 2。下限は掛けない
Seed_c = S_賭式 × P(c)
持ち分_c = Seed_c + その買い目の実票
プール = S_賭式 + その賭式の実票合計
オッズ_c = プール × (1 − D) / 持ち分_c
```

`P(c)` は今の連勝確率である。賭式の中の確率を足すと 1 になる。

払戻は、今どおり買い目の1票ごとに `floor(賭け額 × オッズ)` である。確定配当が 10 倍なら、100 スペの払戻は 1000 スペになる。この関係は S の大きさでは変わらない。

S は賭式ごとに持つ。単勝・馬連・馬単・3連複・3連単で別の値にする。1 億にする必要はない。初期値は、いまの開催設定の S（80,000）を 5 賭式に使う。開催設定で、投票開始前に変えられる。投票開始後は変えない。S は初期オッズを変えない。S が決めるのは、実票が入ったあとに倍率がどれだけ動くかと、薄い買い目の的中で新規発行されるスペの大きさである。

開始時（実票ゼロ）の倍率は `(1 − D) / その買い目の確率` である。

### 当たりの実票がゼロのとき

その買い目を持っている人がいない。特払いもしない。その賭式に投票した馬券は外れとし、スペは戻さない。戻さなかった額は移管の正の側に入る。

当たりの実票が 1 票以上あるときは、上の式（Seed を含む）で払い、投票額を超えてもよい。

### メンバーから見た変化

オッズは投票のたびに止まるのではない。その買い目の Seed が実票より厚いほど、1 票での動きは小さくなる。締切で実票だけに切り替えて数字が飛ぶことはなくなる。投票中の表示と、締切後の確定配当は同じ数字である。呼び方は今どおり、投票中は参考オッズ、締切後は確定配当である。

連勝に入った実票は、単勝のオッズを動かさない。

### 場の会計

移管の式は変えない。

```
移管 = その開催の全投票 − その開催の全払戻・返還
```

正の値は、その開催でメンバーに戻らなかった額である。控除、払戻の端数、当たりの実票がゼロで誰にも払わなかった分を含む。負の値は、その開催で新規発行したスペである。1 開催の中で単勝がプラス、3 連単がマイナスなら、台帳に出るのはその差し引きである。

管理者の残高へ足すのは、移管が正のときだけである。負の移管では残高を減らさない。総発行スペは今どおり「管理者残高 ＋ メンバー所持 ＋ 未精算」であり、負の移管を管理者から引かないことで、メンバーの所持が増えた分だけ総発行が増える。第1回・第2回の正の移管は、今の管理者残高に残す。

精算テーブルの移管額は 0 以上に固定されている。負の値を保存できるよう、この制限は外す。

台帳の上段は次の並びにする。

- 総発行スペを主表示にする。参加で配った分と、移管が負だった開催の発行を含む
- 総払戻スペを足す。公開済み開催の的中払戻の累計。過去開催に残っている特払いは、ここに含めてよい
- メンバー所持合計と未精算プールは今のまま
- 場の管理スペ残高は残し、主表示から外す。正の移管だけが積もる残高である

開催別の「場へ」は「移管」に変える。数字はマイナスのまま出す。説明は「負の値は、その開催で新規発行したスペ」とする。純還元率は 100% を超えた値を、そのまま出す。有効投票・払戻・全額返還の切り分け（やり直しと出走取消を有効投票から除く）は今のままである。

### 過去の開催と、第3回からの記録

過去開催の倍率は、アプリの中では再計算も再表示もしない。金の記録だけを正にする。

- 第1回・第2回の払った額は `payouts`、移管は精算行が正である。再計算しない
- 第1回は分析ログを入れる前に終わっている。倍率の板は残っていない
- 第2回の締切後スナップショットは、当時の確定配当の控えとして分析ログの ZIP に残す。アプリの画面には出さない
- 分析ログは投票中の経過であり、確定の保管には使わない。人気上位と実票のある買い目だけが入り、退避すると D1 から消える

第3回以降は、開催に式の名前を1つ付ける。今回の式は `odds-v4`。既存の開催は `odds-v3` とマークし、新式では計算しない。第1回の中身は `odds-v3` と完全には同じでないが、再計算しないので、このマークは「新式ではない」という意味で足りる。

- 開催を作ったときに式の名前を付ける。第3回の開催から `odds-v4`
- 結果公開のときに、賭式ごとの当たり買い目、その倍率、払戻、移管額をその開催へ保存する。全通りの買い目は保存しない
- 公開後の場内・馬券・台帳は、その保存値を読む
- 分析ログは、その開催の式で投票中の経過を残す。識別子は `odds-v4`。`w`・`E`・`λ`・評価点下限は、効いている値としては記録しない
- ログの列の成形は、別作業「分析ログの成形」で行う。この実装では、新式の板が保存でき、旧式の ZIP と区別できれば足りる

式のコードは1本である。第2回がカレントのあいだは旧式のまま公開まで終える。第2回の公開より前に新しい式へ切り替えると、第2回の払戻が新しい式で決まる。

## 画面

- 会員向けの投票中と締切後は、上の式の同じ数字を出す。締切で実票だけの列へ切り替えない
- 管理のオッズタブにある「実票」列は見比べ用として残す。払戻には使わない。会員向けの確定配当とは別の数字であることが見出しから分かること
- 特払い予定、8割戻し、の案内は、この式の開催では出さない。当たりの実票がゼロの賭式は、その馬券を外れとして示す
- 開催設定から `E`・時間の下限・時間の曲線を外し、S を賭式ごとの5欄にする

# 連勝 Seed と参考オッズ（作業仕様）

**用途:** 「連勝側への Seed と初期オッズを実装する」作業だけで使う引継ぎ資料。チャットで決めた内容をここへ追記・更新し、実装完了後に必要な確定事項だけを [odds.md](odds.md) と [analysis-log.md](analysis-log.md) へ反映する。

**段階:** 要件検討中（2026-09-20）。この資料は現時点の合意と候補を分けて記録する。未決の式を実装しない。

## 未決事項（実装前に決めること）

- 連勝用評価点に下限を入れるか。入れる場合の値。
- 管理画面・場内・窓口・API・分析CSVの各表示対象。
- 数式変更に伴う `formula_version`（候補: `odds-v3`）と分析CSVの列追加。

## 決まったこと

- 対象は馬連・馬単・3連複・3連単。単勝の現行参考オッズと、締切後の確定配当の計算は変えない。
- 投票中の連勝オッズは、評価点由来の仮想的な Seed を使う演出用の参考値にしてよい。ゲームとしての見え方・楽しさを優先する。
- 締切後の確定配当と実際の払戻は、全賭式とも実票だけで計算する。Seed・評価点・参考オッズを払戻へ混ぜない。
- 表示上限は **`9999.9倍以上`** とする。極端に低い評価点を含む組み合わせが、天文学的な参考オッズになっても生値をそのまま出さない。

## 推奨する基本式

評価点から各馬の基礎確率を作る。連勝用に人気差を強める場合は指数 `γ` を使う。

```text
q_i = 評価点_i^γ / Σ 評価点^γ
```

`γ=1` は単勝の現行 Seed と同じ比率。`γ>1` は人気どころをより強くし、連勝の最人気組み合わせを低い倍率へ寄せる。

順番のある買い目は、上位着順を順に選ぶ確率として計算する。

```text
P(i→j) = q_i × q_j / (1 − q_i)

P(i→j→k)
= q_i
× q_j / (1 − q_i)
× q_k / (1 − q_i − q_j)
```

順不同は成立する順序をすべて足す。

```text
P(馬連 i-j) = P(i→j) + P(j→i)

P(3連複 i-j-k) = 6通りの P(i→j→k) の合計
```

各賭式内では、全買い目の確率の合計が1になる。よって賭式ごとに同じ仮想プール `S` を配れる。

```text
連勝Seed_c = S × P(c)
Display_c = 連勝Seed_c × w + Real_c
連勝参考オッズ_c = {Σ Display × (1 − D)} / Display_c
```

`Σ Display` は、その賭式について `S × w + その賭式の実票合計` となる。`w` と `D` は、まず単勝で使っている開催の値を共用する案を基準にする。

確定配当は従来のままとする。

```text
確定配当 = その賭式の実票合計 × (1 − D) / 当たり買い目の実票
```

## Imputed（単勝への連勝実票の反映）

**現行仕様を維持する。** 連勝の実票は、買った賭式の参考オッズを直接動かすと同時に、単勝参考オッズの人気にも反映する。

- 馬連: 1:1
- 馬単: 2:1（1着候補を厚くする）
- 3連複: 1:1:1
- 3連単: 3:2:1
- `λ=1` を維持する

第1回では単勝実票22,700に対し連勝側実票が24,600あった。単勝だけの投票を単勝へ反映する方式に変えると、場全体の投票の半分強を単勝人気から除くことになるため採らない。連勝の仮想Seedは単勝へ混ぜず、実票だけを従来どおり Imputed する。

## `γ` の状態

**採用する。仮値は `γ=2`。** 実装後にアプリ上の数字を見て最終値を決める。`γ` の値だけを調整する場合も、試算結果と判断理由をこの資料に残す。

- `γ=1`: 単勝の評価点比と完全に揃う。一方、17頭の混戦では最人気3連単も約870倍になりやすい。
- `γ=2`: 連勝の人気差を適度に強める仮値。現ローカルDBの17人では最人気3連単が約400倍になる。
- `γ=3` 以上: 最人気はさらに実競馬らしい低めの数字へ寄るが、低評価馬を含む組み合わせがより極端になり、単勝との人気感も離れる。

`γ` を採る場合も、評価点の下限を別途設けるかは未決。表示は上限表記で守ることを先に決めた。

## 賭式別 E（第2回の試用値）

**賭式ごとに E を持たせる方針を採用する。** 開始時の連勝 Seed は各賭式で `S=80,000` を使い、賭式ごとの実票によりそれぞれの Seed を薄める。仮想Seedは賭式間で取り合わない。

第2回特別レースでは、前回より馬連以外の連勝券種への投票が増えることを見込み、次の試用値から始める。

| 賭式 | E |
|---|---:|
| 馬連 | 25,000 |
| 馬単 | 7,000 |
| 3連複 | 7,000 |
| 3連単 | 7,000 |

前回と同じ締切時の時間側 `w時=0.8`、`S=80,000` とし、各賭式の表示プールに占める有効Seedの割合が42%になる実票額を逆算すると次のとおり。

| 賭式 | E | Seed比率42%に達する実票額 |
|---|---:|---:|
| 馬連 | 25,000 | 約19,488 |
| 馬単 | 7,000 | 約6,486 |
| 3連複 | 7,000 | 約6,486 |
| 3連単 | 7,000 | 約6,486 |

これは馬連については第1回実績19,300に近く、他3賭式はそれぞれ前回実績（馬単100・3連複3,300・3連単1,900）を上回る投票を期待する設定である。前回実績のままでは、他3賭式はSeed比率42%には達しない。

## 現ローカルDBでの試算（2026-09-20）

対象はローカルDBのカレント開催「第１回メンバーシップ特別レース（ローカル確認用）」の17人。`S=80,000`、`D=20%`、投票開始直後（`w=1`）で計算した。評価点合計は1,674.5。

`γ=2` の3連単:

| 区分 | 買い目 | 開始時参考オッズ | Seed | 100スペ投票後の参考オッズ |
|---|---|---:|---:|---:|
| 最人気 | 10→8→3（マヤノトップガン→ステイゴールド→シュヴァルグラン） | 400.1倍 | 約160.0 | 約246.4倍 |
| 最不人気 | 14→15→5（マンハッタンカフェ→ゼンノロブロイ→オグリキャップ） | 約190億倍 | 約0.000003 | 約640.0倍 |

14番を除外して16人へ Seed を配り直した場合の最不人気は、15→5→4（ゼンノロブロイ→オグリキャップ→ナリタトップロード）。開始時は約87.9万倍、Seed は約0.073、100スペ投票後は約639.7倍。

100スペ投票後は、投票額により `w` がわずかに下がる分も含めている。`E=100,000` のため差は小さい。

## メンバーへの表示（検討中）

18頭立てでは全組み合わせが、馬連153・馬単306・3連複816・3連単4,896通りになる。全件を画面・5秒更新API・分析CSVへ常に出すのは避ける。

決まったこと:

- 場内の単勝一覧と同じ場所を、`単勝 / 馬連 / 3連複 / 馬単・3連単` の4タブで使う。単勝タブの表示・CSSは現行の本番相当を維持する。
- 馬連はJRA公式サイトに近い縦読みの三角表で全組み合わせを表示する。各列は軸ウマ娘のウマ番を見出しにし、見出しの左右へウマ柱と同じ枠色を付ける。1番列は2番から、2番列は3番から始め、各列を上揃えにする。
- 3連複は順不同であることを明示した「軸ウマ娘」選択で1頭を指定し、残る2頭の組み合わせを馬連と同じ三角表で表示する。表の左端には選択中のウマ番・ウマ娘名を縦書きで示す軸ウマ娘パネルを置き、押すと出走ウマ娘一覧のモーダルを開いて軸を変更できる。
- 馬単・3連単タブは、馬単・3連単の2パネルを横並びにする。各パネル内は「人気上位」「直近に実票が入った買い目」の2列とし、それぞれ最大9件を表示する。各列の間には罫線と余白を設け、投票列の買い目は罫線からさらに左余白を取る。表示領域内に縦スクロールを出さず、買い目・オッズを読み取れる文字サイズで表示する。
- 三角表では最後の馬番を軸列として出さない。馬連の主表は18・17人で1〜10、16・15人で1〜9、14・13人で1〜8とする。3連複は左端の軸ウマ娘パネルを除き、18人で2〜11、17・16人で2〜10、15人で2〜9とする。副表は残りの軸列を逆順にして主表右下の空白へ置き、主表の表示列数と選択中の軸列に応じて右端を揃える。
- 各タブの電光掲示板の表示領域は、単勝タブの実測高さを共通の基準にする。画面サイズ変更・Webフォント読込後にも再計測し、内容が収まらない場合は外枠を伸ばさずタブ内をスクロールする。数値固定や透明要素での高さ合わせはしない。
- タブ切替はレース名の直下に電光掲示板幅いっぱいの「表示切替」帯として置く。4タブは同じ幅を基本とした独立タブとし、選択中は下の表示面へつなげ、均一な橙色の枠線と文字で明確化する。PCではレース名をタブ帯より大きく見せ、モバイルではタブ列だけを横スクロールできる。
- 窓口では、買い目を選び終えた時点で、既存の「自分の馬券」表示エリアにその買い目の現在のオッズを出す。購入馬券の一覧ページを別途作る予定のため、このエリアを有効活用する。
- PC電光掲示板は16〜18頭の開催で縦幅に収める。連勝の表示行数を無制限に増やさない。
- 内部では任意の買い目を都度計算できるようにし、全通りの Seed をDBへ保存しない。

単勝表示を本番と同じ見た目のまま比較するため、ローカル限定で場内コンポーネントを使う確認画面を用意する。`npm run dev` 中に `/__local/venue-odds` を開くと4タブを確認できる。画面外左下の「表示頭数」で15〜18人を切り替え、三角表の配置を確認する。この段階の連勝側の数字はレイアウト検討用の静的表示であり、Seed・参考オッズの計算結果ではない。

分析ログは、実票のある買い目に加え、各賭式の人気上位を記録する案を検討する。

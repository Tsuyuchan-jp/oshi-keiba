# 投票とオッズ

## パリミュチュエル

オッズを運営が事前に「正しい値」として置かない。プールを的中者の投票比率で分ける。

Neko長明さん投稿の式（単勝のイメージ）:

`オッズ = (総投票額 TV × (1 − 控除率 D)) / (その馬への投票額 V)`

- D の目安: 20%（JRA 基準として言及された値）
- 少人数（目安 20 人）だと実投票だけではオッズが荒い・変動が極端、という問題が投稿の核心
- だから初期の V（シード）と、実投票の取り込み方（投稿では UV の重み、倍率、ブレ）が要る
- 投稿の「AI がステとスキルから強さを評価して V を置く」が、作者モデルの根拠

完璧な「もっともらしさ」は体裁の質の話。体裁の有無に必要なのは:

1. 締切後の正確な配当計算（実ポイントのみ）
2. 投票中にオッズらしき数値が見えること（Seed 込みの表示）

素朴な表示で動かしてから縮小推定に差し替える、という順序は残してよい。

## 表示式

`Display_i(t) = Seed_i × w(t) + Real_i(t)`

清算と表示は分ける。

- **清算**: 実ポイント `Real` だけのパリミュチュエル。控除 D=20%。Seed は誰の持ち分でもないので、配当に混ぜない（混ぜると幽霊投票が的中者の取り分を食う）
- **表示**: Seed を足した `Display` でオッズを見せる。少人数でも開始直後に無限オッズにならない

`w(t)` の fancy な減衰（時間カーブ、ユーザーごとの倍率ブレ、Neko投稿の 4000 倍）は体裁の磨き。今は置かない。

### いまの粒度（B と同じ考え方）

曲線の式ではなく、効き方の錨を置く。

| 場面 | 体感 |
|---|---|
| 投票開始直後 | 作者モデルの並びがそのまま初期オッズに見える（Seed が本体） |
| 標準的な1人が本命に張ったとき | 板が書き換わるほどではないが、**ちょっと動いた**と分かる |
| 締切近く、そこそこ投票が入ったあと | 実投票の偏りがオッズに見える。Seed は残っていて極端な穴・極端な固定にはしにくい |
| レース確定後の払い戻し | Seed は無視。実ポイントと D=20% だけ |

開始直後を Seed 本意にし、1票で「ちょっと動く」なら、**Seed 総量と週次配布・賭け上限の比**が実質の `w` である。時間で `w(t)` を減らすのは、その比が決まったあとのオプション。

時間減衰を先に置くと、誰も賭けていないのに時計だけでオッズが変わる。情報が増えていないのに板が動くので、今は採用しない。

## ポイント発行（仮の錨）

数字は後で変えられる。単位の名前だけ揃える。

- **毎週の配布**: 1人が「本命に厚く、穴に少し」できる枚数。細かい 1 ポイント単位の戦略は要求しない
- **1頭への賭け上限**: 所持の全額を1頭に沈められると、20 人規模では板が壊れる。上限は置く
- **1レースの合計上限**: なくてもよい。頭の上限があれば、全頭に薄く撒くのは実投票として自然
- **Seed 総量**: 週次配布 × 想定参加人数（目安 20）と同じ桁。これで「開始は作者オッズ、1票でちょっと動く」が両立しやすい

景品への交換は後回し。ポイントは換金できない。

Neko投稿の「1票を 4000 倍」「ユーザーごとにブレ」は、少人数をダービーの入場者に見せかける演出。MVP では Seed 総量の比で代用し、後から差し替えてよい。

- MVP: 単勝のみ
- 複勝・連勝式はプールを賭式ごとに分ける必要があり後回し
- 計算レイヤは賭式を足せる形にしておく

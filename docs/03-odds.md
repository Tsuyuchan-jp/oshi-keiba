# 投票とオッズ

> **再検討中（2026-08-19）**  
> `w`・Seed の表示／清算、オッズの見せ方は決定していない。以下の表示式・段差・ラベルの節は対話の途中メモ。質問のたびに採用へ固定しない。パリミュチュエルが本体であること、Seed は作者モデルから置くこと、まではプロダクト前提。

## パリミュチュエル

オッズを運営が事前に「正しい値」として置かない。プールを的中者の投票比率で分ける。

Neko長明さん投稿の式（単勝のイメージ）:

`オッズ = (総投票額 TV × (1 − 控除率 D)) / (その馬への投票額 V)`

- D の目安: 20%（JRA 基準として言及された値）
- 少人数（目安 20 人）だと実投票だけではオッズが荒い・変動が極端、という問題が投稿の核心
- だから初期の V（シード）と、実投票の取り込み方（投稿では UV の重み、倍率、ブレ）が要る
- 投稿の「AI がステとスキルから強さを評価して V を置く」が、作者モデルの根拠

完璧な「もっともらしさ」は体裁の質の話。体裁の有無に必要なのは:

1. 締切後の正確な配当計算（実ポイントのみ）
2. 投票中にオッズらしき数値が見えること（Seed 込みの表示）

素朴な表示で動かしてから縮小推定に差し替える、という順序は残してよい。

## 表示式

`Display_i(t) = Seed_i × w(t) + Real_i(t)`

清算と表示は、**同じ「オッズ」という名で別の数字を出さない。** 最終オッズと配当がズレる運用は、作者の感覚では大問題（競馬では確定オッズが配当そのもの）なので採用しない。

三角関係:

- 表示 = 配当 = 実点だけ → 少人数で確定板が暴れる。Seed は途中の参考にしか使えない
- 表示 = 配当 = Seed 込み → その倍率で払う必要がある。穴の週は実プール不足（増刷か運営負担）
- 表示は Seed 込み、配当は実点 → 数字が二つ。板は連続するが、見た目が嘘になる

採用するラベル分け:

- **投票中**: Seed 込みは「参考オッズ」（作者モデル＋これまでの票）。賭け事の確定値とは呼ばない
- **締切後**: 「確定オッズ」と配当は **実ポイントのパリミュチュエルだけ** で一致させる。控除 D=20%

直前の参考と確定のあいだに差は出る。投票が少ないほど大きい。それは「最終オッズが嘘」ではなく、「参考が外れた／票が少なかった」と読める。JRA の途中オッズが確定で動くのと同型で、途中に Seed が乗っている分だけ差は実投票制より大きくなりうる。

Seed を確定に残して表示どおりに払う案、時間減衰で参考を確定に寄せる案は、それぞれ増刷と締切前の暴騰になるので本線にしない。

`w(t)` の fancy な減衰（時間カーブ、ユーザーごとの倍率ブレ、Neko投稿の 4000 倍）は体裁の磨き。今は置かない。

### いまの粒度（B と同じ考え方）

曲線の式ではなく、効き方の錨を置く。

| 場面 | 体感 |
|---|---|
| 投票開始直後 | 作者モデルの並びがそのまま初期オッズに見える（Seed が本体） |
| 標準的な1人が本命に張ったとき | 板が書き換わるほどではないが、**ちょっと動いた**と分かる |
| 締切近く、そこそこ投票が入ったあと | 実投票の偏りがオッズに見える。Seed は残っていて極端な穴・極端な固定にはしにくい |
| 投票中 | 参考オッズ（Seed 込み）。確定値とは呼ばない |
| 締切後の確定オッズと払い戻し | 同じ式。実ポイントと D=20% だけ。表示と配当は一致 |

開始直後を Seed 本意にし、1票で「ちょっと動く」なら、**Seed 総量と週次配布・賭け上限の比**が実質の `w` である。時間で `w(t)` を減らすのは、その比が決まったあとのオプション。

時間減衰を先に置くと、誰も賭けていないのに時計だけでオッズが変わる。情報が増えていないのに板が動くので、今は採用しない。

## 締切直前と確定の差

参考（Seed 込み）と確定（実点）は、投票が少ないほど離れる。これは残る。カバーは「確定オッズ」を嘘の数字にしないこと。差は参考が外れた、と説明する。

以前の案（締切後も Seed 込みを最終オッズとして凍結し、配当だけ実点）は、同じ「オッズ」で払わない数字を出すことになるので却下。

やってはいけない本線:

- Seed 込みの倍率で全額払う（穴の週に増刷。ブックメーカー）
- 締切に向けて `w(t)` を 0 に落とす（投票が少ないと、確定と同じ暴騰が締切前に起きる）

## 賭式

- MVP: 単勝のみ
- 複勝・連勝式はプールを賭式ごとに分ける必要があり後回し
- 計算レイヤは賭式を足せる形にしておく

## ポイント発行（仮の錨）

数字は後で変えられる。単位の名前だけ揃える。

- **毎週の配布**: 1人が「本命に厚く、穴に少し」できる枚数。細かい 1 ポイント単位の戦略は要求しない
- **1頭への賭け上限**: 所持の全額を1頭に沈められると、20 人規模では板が壊れる。上限は置く
- **1レースの合計上限**: なくてもよい。頭の上限があれば、全頭に薄く撒くのは実投票として自然
- **Seed 総量**: 週次配布 × 想定参加人数（目安 20）と同じ桁。これで「開始は作者オッズ、1票でちょっと動く」が両立しやすい

景品への交換は後回し。ポイントは換金できない。

Neko投稿の「1票を 4000 倍」「ユーザーごとにブレ」は、少人数をダービーの入場者に見せかける演出。MVP では Seed 総量の比で代用し、後から差し替えてよい。

具体枚数（1000 か 10000 か）と、1頭上限を所持の何割にするかは未決。

## 想定総量と週次配布（検討中・未採用）

票量側 `w` の「半分」は、実票量 ÷ **想定総量 E** がだいたい 0.5 のとき。E を週次配布 G からどう出すかが次の層。

結び方の候補（まだ選ばない）:

- E を G × 想定人数（20）で自動算出する（使い切る前提だと分かりやすい。G を変えると E も追従する）
- さらに使用率を掛ける（全員が全額は賭けない、という体感）
- E を管理者 UI の独立項目にする（`w` 曲線と同じく後から触る）

ポイントが週をまたいで残るかで、E の意味が変わる。残るなら「今週の配布 × 20」より実票が大きくなりうる。作者感想は残る（仮想資産）寄り。未本採用。

## 対話ログ（採用ではない）

- 投票中の大きい数字は、払う約束より **作者モデル＋これまでの票の人気の目安** に寄せたい
- 金銭ではないので、参考と確定の正確な一致は犠牲にしてよい。ただし乖離が大きすぎると投票ツールとしての信頼を失いそう
- 時間だけで `w` を強く減らすのは以前避けた。実投票が増えると `w` が減るのを主に、時間では薄く減らす両輪はありうる、という作者案。未採用
- 「荒れる」は投票0件の横並びではない。閑散で `w` が小さく、実票が1頭に偏ったときに、その頭だけ超低オッズ・他が超高または計算不能、という形。実票0件で `w` が全頭共通なら、オッズ比は Seed と同じまま。
- 投票中に作者並びを残す（`w` 下限が厚い）ても、確定・払い戻しを実票だけのパリミュチュエルにするなら、締切後は閑散時の「荒れた」計算になる。この切り分けの認識は作者と一致。未採用の前提の話。
- トレードオフの言い直し（作者）: `w` 下限が厚い → 2人目にも目安が残るが、確定との乖離は大きい。下限が 0 近い → 2人目の見た目は荒れるが確定との乖離は小さい。閑散週をどれだけ重視するかも含め未決。正解はない、という認識で一致。
- 仮置き（作者・未本採用）: 様子を見て定数は変えられる前提で、**時間側の `w` 下限は厚め**。この下限は時間操作にだけ付ける。票量で薄くする側の下限は 0 でよい（票が乗れば Seed を表示から消してよい）。票量→`w` の効きの強さは未決。組み合わせは、時間だけでは 0 まで落とさず、票量だけでは 0 まで落とせる形。以前の「合成した一つの `w` 全体に下限」とは別物。
- 票量側の錨（作者の素人体感・未本採用）: 想定 MAX を 20 人分の票量としたとき、その半分（10 人分相当）が乗ったら票量側 `w` はだいたい半分。操作の入力は人数ではなく **実票の量**（1人一票にするかは未決なので、人数カウントだと鯨に壊される）。曲線の形はまだ置かない。
- **仮置き本採用（作者）**: `w` は初期値より、下限・曲線を管理者が UI で変えられること。初期値は上の錨でよい。想定総量と週次配布の結びは次の対話。
- ポイントはユーザーの仮想資産（貯めて来週厚く張れる）に寄せたい、という作者感想。週次使い切りではない。ユーザー別残高があるなら登録・認証が要る、という見立て。未本採用。

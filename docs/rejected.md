# 見送った案

再検討するときは、ここに書いた却下理由が今も成立するかだけ見る。

## GitHub Pages でホストする

静的配信だけで共有の残高・投票を持てない。仮パスワードをフロントに置くと秘匿にならない。公開は Cloudflare。Pages は見た目の静的プレビュー以外では使わない。

## 実ゲームのリプレイから実況・着順を取る

メモリ読み・パケットは規約的にグレー〜アウト。公式エクスポートもない。着順用の OCR／動画はコストに見合わない。採用しない。本戦のステータススクショ読み（[ocr.md](ocr.md)）とは別件。

## シミュ実況

umasim のログで実況する案は、作者のモチベーションに合わない。採用しない。

## ブックメーカー（固定オッズ）

運営が損失リスクと調整を負う。少人数イベントには向かない。パリミュチュエルを採用。

## 初期シードを Neko長明さんの3連単予想にする

実装は軽い。ただし「製作者がステとスキルから V を置く」を放棄する。Seed の入力にはしない。比較・答え合わせ用途には残しうる。

## WASM タイムから勝率 → Seed

単走リサンプリングも多頭改修も、Seed の前提にしない。単走はポジションキープで脚質バイアスが残る。「正しい勝率」目標は検証手段不足で詰む。

## ツール側の「せーの」演出

note が既に予想・実況・結果提示を担う。独自カウントダウンは作らない。

## 投票中にゲーム飛び入りをアプリ名簿へ足す

飛び入りはルールで禁止。起きた場合のアプリ扱いは要検討（ゲーム内再出走が分かりやすい案）。投票中に名簿を足して Seed を組み直す本線にはしない。

## 実レース後〜予想 note 直前まで投票を開ける

ゲーム内ですでに着順を見た人が賭けられる。締切は着順が見える前。

## 最終オッズと配当をずらす

締切後も Seed 込みを「最終オッズ」として出し、払いだけ実点にする案。見た目が嘘になる。却下。投票中の Seed 込みは参考、確定と配当は実点で一致。

## 単勝参考の均一 Display フロア（F）

第2回の仮値比較で不採用。票の見え方を床で揃えない。

## 開催ごとに DB を初期化する

第1回を一度回すための逃げ。残高の持ち越しと開催の記録を捨てる。本線は「次の開催を開く」。デモ初期化はローカル実機だけ。

## 作者独自の評価点（旧 Strength）

U-tools バ身と場内相対化（混ぜ B、スキル 3 : ステ 1、温存錨）は、Neko 案の評価点に置き換える。詳細は git の旧 `docs/04-strength-model.md` ほか。当時の「混ぜ A（共通基準の絶対点）」も作者案同士の比較であり、現行の評価点とは別。

## 特払いのキャリーオーバー

仮想ポイント（スペ）を景品に交換する運用では、キャリーオーバーはギャンブル性を高めすぎる。Neko長明さんへの確認で見送り。特払い B（控除後の8割戻し）を維持し、キャリーオーバーは実装しない。

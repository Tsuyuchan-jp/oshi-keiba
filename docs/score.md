## ここまで確定

- **金**: 有効に含めたうえで +2。`S0 = 有効スキル数 + 2 × 金` → 通常1・金3。Neko記事の「金は白3つ分に近い」と一致
- **加算先**: スピード・スタミナ節の「パワーの実数値に加算」は誤字。その節のステへ足す
- **根性節**: 「要求パワー」は要求根性の誤字
- **無効スキル**: たたき台の表は使わない。U-tools の金ドット36コース×脚質の有効リストを正にする。取得は `umamusume-inherit-skill-list` の `data/effects`（`extract:effects`）。sp-calc には無い
- **達成倍率（仮置き A）**: `S *= 1 + (r−1)/N`。N は速・パ=4、根=10、賢=1（本文に ÷ なし = `S *= r`）
- **未達倍率（仮置き）**: `S *= max(0, 1 + (r−1)×M)`。M はパ=4、根=2、賢=6。`1+(r−1)×M` は `1−M(1−r)` と同じ
- **スピード（仮置き）**: 未達は見ない。対人・このコミュニティではカンストが前提。要求スピードは **継承の上限突破を入れないカンスト値**。A（N=4）が効くのは突破でカンストを超えた分だけ。数値そのもの（1200 等）はシナリオ依存で、定義は「突破なし上限」
- **適性S（仮置き）**: [ウマ娘スクール ステータスと適性](https://umamusumeschool.com/status_aptitude/) を正。A を ×1。S だけ倍率。B 以下はたたき台が「Sか」なので ×1（減点しない）。距離S→速 ×1.1（サイトは約1.1、仮は 1.1）。バ場S→パ ×1.05。脚質S→賢 ×1.1（発動率には掛けない）
- **緑（仮置き）**: 枚数+1 は使わない。内部データの対象ステ上昇を、**開催条件＋頭の脚質で条件を満たす緑だけ**実数値に足す。マスタは `src/data/green-skills.json`。判定は `greenCondition.ts`（`@`=OR、`&`=AND）。人気・枠・抽選・同スキル頭数など手打ちに無いキーは不成立。OCR の `skill-catalog.json` の green（固有の緑アイコン）とは別
- **開催条件（仮置き）**: レース単位で手打ち。コース（場・距離・回り等）、天候、バ場状態、季節。有効スキルリスト（U-tools 36）にも同じコース情報が要る。緑の条件判定と共有する
- **脚質（仮置き）**: 頭ごと。OCR 時に人間が選択。OCR の脚質適性に **S が1つだけ**あれば、その脚質を初期選択にする。S が0または複数、または読取なしなら未選択（人が選ぶ）。変更可
- **補正の順（仮置き・作者確認）**: 生値 → 緑加算 → 適性S倍率 → r
- **デバフ（仮置き）**: ためらい4種だけ名前と mdb id で見て、1つにつき有効 +1（白と同じ）。金の +2 は載せない。それ以外の妨害（けん制・焦り・まなざし・緑× など）は特別扱いしない。U-tools の無効判定で落ちる想定
- **ためらい4種**: 逃げためらい `200851`、先行ためらい `200881`、差しためらい `200911`、追込ためらい `200941`。`kind === minus` では取れない。minus は緑×。ためらいは白（`rarity: 1`、`iconId: 30011`）。カタログ未収録なので OCR は今 `unknown` になり得る。照合は名前または id
- **要求パ・根・賢（仮置き）**: 全コース表は作らない。開催ごとに人間が目標値を確認して入れる（レース単位。頭ごとではない）。シナリオ・サポカで同じコースでも目標が変わる。4ヶ月で新シナリオ、その間の開催は多くて8回程度なので、全表のメンテは割に合わない
- **要求スタミナ（仮置き）**: 同じく開催ごとの手入力。掛かりなし／掛かりありの2値。スタミナ勝負コースは開催フラグ。有志ツールの移植はしない（ツールは確認用に外で使ってよい）

## 読み（未確定）

全体は一本の掛け算パイプライン。スキル数で土台を作り、5ステで倍率を順に掛ける。ゴールは勝率検定ではなく、Nekoさんの強さの論理を数字にすること。

### スキル数（土台）

1. スクショのスキルを列挙する
2. 今のレースで無効なものを落とす
3. 今の脚質で無効なものを落とす
4. 緑はスキル数に入れない（後でステ加算に回す）
5. ためらい4種は名前または id で拾い、有効 +1。他の妨害は無効リストに任せる
6. 残った有効スキルを数える
7. 金の枚数×2 を足す（ためらいは金カウントに入れない）

無効は「有効リストに無いものを落とす」。リストの正は上の確定（U-tools 36コース×脚質）。

### ステ共通の型

各ステはだいたい次の形。

- 目標値は開催ごとに手入力（パ・根・賢、スタミナは掛かりなし／あり。速は継承突破なしカンスト。スタミナ勝負は開催フラグ）
- 実数値はスクショの生値＋緑の内部上昇
- 補正: その節の適性Sならサイト倍率。スピードは距離S、パワーはバ場S、賢さは脚質S
- 達成比 `r = 補正後実数値 / 目標値`
- 達成時は S を r に応じて伸ばす。未達時はペナルティ（**スピードは未達を見ない**）

### 「実数値÷目標値÷４の値だけSを倍にする」

同じ型が4節ある。

| 節 | 原文の X | 直後 |
| --- | --- | --- |
| スピード | 実数値÷目標値÷４ | なし |
| パワー | 同じ | 「この値が1.0を下回るの場合…」 |
| 根性 | ÷１０ | 同じ「この値」 |
| 賢さ | 実数値÷目標値（÷なし） | 同じ「この値」 |

文法の芯は **「Xの値だけSを倍にする」**。÷４は X の一部で、「倍」は ×2 ではない。賢さに ÷４ が無いのに同じ「倍にする」があるので、「倍」= **倍率を掛ける** の口語。

`r = 実数値 / 目標値` と置く。

**「この値」は r であって r/4 ではない。** パワーで r/4 を 1.0 と比べると、実数値が目標の4倍未満なら常に未達側へ落ちる（ウマ娘では常時）。1.0 判定を書く意味が無い。だから ÷４ は達成側の加減だけ。未達は別文。

字面どおり `S *= r/4` は、目標ちょうど（r=1）で S が 1/4 になる。土台のスキル数を壊す。**字面は棄却。**

残りは、「賢さは r をそのまま倍率にする」を原型とし、スピード／パワー／根性はそれを **弱めた書き方** と見るか。

賢さを原型にすると、達成側の意図は `S *= r`（r=1 で据え置き、超過は比例）。弱め方の書き損じが ÷４。

| 候補 | 達成の式 | r=1 | r=1.2（2割超過） | 注記との相性 |
| --- | --- | --- | --- | --- |
| A | `S *= 1 + (r−1)/N` | ×1 | N=4 なら ×1.05 | 「達成メリット少ない」= 超過の効きを 1/N にする。÷N を **差（r−1）** に掛けた形。書きは r÷N になっている |
| A' | `S *= 1 + r/N` | N=4 なら ×1.25 | ×1.30 | 「の値だけ」を加算と読む。目標達成時点で既に +25%。メリット少ないとやや矛盾 |
| B | `S *= r`（÷N は無視） | ×1 | ×1.20 | 賢さと同一。÷４が死ぬ |
| C | `S *= r/N` | ×0.25 | ×0.30 | 棄却 |

**達成は仮置き A。** 根拠は (1) 賢さ節が `S *= r` と読める (2) `1+(r−1)/1 = r` で賢さと同型 (3) ÷４／÷１０は超過の効きを薄くする係数 (4) 目標ちょうどで土台を壊さない (5) パワー注記と矛盾しない。

書きとの差: 本文は `r/4`、A は `(r−1)/4` を 1 に足す。**比そのものを割る**と **超過分だけを割る** の取り違え。口語の「÷４の値だけ」は後者。

### 「１－目標値を４倍」

未達側。目標が千点台だと字面は意味をなさない。達成 A と同じく、差は `r−1`（未達なら負）。

「１－目標値」→ `1−r` = `−(r−1)`。「をM倍」→ その差を M 倍。掛けるのは差そのものではなく、達成と同じ **1 に足す**。

`S *= max(0, 1 + (r−1)×M)`

`(r−1)×M` だけを倍率にすると r<1 で負になり S が壊れる。A の「同じく」は **差に係数を掛けて 1 に足す** の側。

検算: `1 + (r−1)×M = 1 − M(1−r)`。r=1 で達成・未達とも ×1。パワー M=4・1割不足（r=0.9）は ×0.6。r≤1−1/M で 0（パワーは 75% 未満で評価点 0）。

注記との対応:

- パワー: 達成メリット小・未達デメリット大 → N=4, M=4
- 根性: 未達は軽い → N=10, M=2
- 賢さ: 両方大きい → N=1, M=6
- スピード: 未達なし。要求は継承突破なしのカンスト。超過（突破分）だけ N=4

たたき台にスピード未達が無いのは、書き漏れではなく **起きない前提**。実装も r<1 なら掛けない（×1）。起こったらデータ異常として直置き側で見る。

### 節ごとの補正

適性Sと緑は仮置き（上）。順は **生値 → 緑の内部上昇を加算 → 適性Sなら倍率**。根拠: 緑は同じステの上昇。適性Sは「そのステの効き」。先に足してから倍率する方が、育成で盛った分と緑が同じ土俵になる。逆（適性→緑）だと、S馬の緑だけ倍率の外に出て薄い。サイトの体力式も「スタミナ＋緑」を括弧の中に置き、そのあと係数を掛けている。差は緑が大きいとき以外は小さい。

- スピード: 距離Sなら ×1.1。スピード緑の内部上昇を加算
- スタミナ: スタミナ緑の内部上昇を加算（掛かりの有無は目標側。適性倍率なし）
- パワー: バ場Sなら ×1.05。パワー緑の内部上昇を加算
- 根性: 緑も適性も無し。要求は根性
- 賢さ: 脚質Sなら ×1.1。賢さ緑の内部上昇を加算。発動率の式には使わない

サイト同ページの「1200超は半減」は、今回の指示に含まれない。仮置きには入れない。

### スタミナ（離散ペナルティ）

他ステと違い、倍率は固定。

- 掛かりなし目標も未達: ×0.4
- 掛かりあり目標だけ未達（掛かりなしは達成）: ×0.8
- 両方達成: 本文に倍率なし → ×1
- 「スタミナ勝負のコース」なら代わりに ×0.2 と ×0.4
- `0,4` は `0.4` の誤記

掛かり発生時の要求 ≥ 未発生の要求、が普通。両方未達は「未発生が未達」に含まれる、と読める。両方達成の加点は書いていない。

### 作業用の式（仮置き）

金3・加算先・A と未達 `1+(r−1)×M`。Neko確定ではない。

```
S0 = 有効スキル数 + 2 × 金スキル数
// ためらい4種（200851/200881/200911/200941）は白1。他の妨害は U-tools 無効に任せる

r速 = (速 + 緑速内部上昇) × (距離S ? 1.1 : 1) / 要求速   // 要求速 = 継承突破なしのカンスト
S *= r速≥1 ? 1+(r速−1)/4 : 1   // 未達は見ない

掛かりなし未達 → ×0.4（スタミナ勝負コースなら ×0.2）
掛かりありのみ未達 → ×0.8（同 ×0.4）
判定のスタミナ = スタ + 緑スタ内部上昇

rパ = (パ + 緑パ内部上昇) × (バ場S ? 1.05 : 1) / 要求パ
S *= max(0, rパ≥1 ? 1+(rパ−1)/4 : 1+(rパ−1)×4)

r根 = 根性実数値 / 要求根
S *= max(0, r根≥1 ? 1+(r根−1)/10 : 1+(r根−1)×2)

r賢 = (賢 + 緑賢内部上昇) × (脚質S ? 1.1 : 1) / 要求賢
S *= max(0, r賢≥1 ? 1+(r賢−1) : 1+(r賢−1)×6)
```

これが評価点。場内で比にして Seed にする（[odds.md](odds.md)）。

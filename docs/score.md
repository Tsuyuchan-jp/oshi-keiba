## 現在の式調整（案B・実装済み）

**案B** を採用した。現行のステータス補正は残し、スキル土台 `S0` の差だけを累乗で強調する。基準点 `b` は `90` とする。

```text
評価点 = b × (S0 ÷ b)^n × ステータス補正の積
// 今回は b = 90
```

キャラスペック補正をスキル点に掛ける。

```text
E = 出走馬が実際に持つ固有・進化スキルの有効バ身数の合計
R = 取得した当該コース全キャラの合計有効バ身数の中央値
キャラスペック倍率 = clamp((E ÷ R)^0.20, 0.85, 1.20)
スキル点 = 90 × (S0 ÷ 90)^n × キャラスペック倍率
```

U-tools の通常「有効キャラ」ページをコースごとに取得し、キャラ数・合計値・固有／進化スキルごとの値を `events.score_setup.characterSpecs` にスナップショット保存する。照合はスキルID。取得失敗または一致スキルなしは倍率 `×1.00` とする。

- `n=1` は現行式と同じ
- `n>1` は、スキル土台の低い馬をより低く、高い馬をより高くする
- スキル土台が近い馬同士では、現行どおりステータス補正が差を作る
- `b` は評価点の桁を整え、直置き評価点との見比べにも使う。全自動算出馬どうしのSeed比率・初期参考オッズの差を作るのは `n`
- 直置き評価点は、人が他馬の評価点を見て調整する運用とし、この式の対象外
- `n` の既定値は `4.5`。開催設定から `1.0〜10.0` の範囲で `0.1` 刻みに調整できる
- 今回の実データでは、しょーじさんのセイウンスカイとつゆちゃんさんのアドマイヤグルーヴがおおむね 6：5 となる値として `4.5` を採用した

**案A（保留）**: 開催ごとの標準S0を基準点 `b` として保存し、`max(0, b + n × (S0 − b))` を調整後スキル点にする方式。切れ者の有無などでS0分布が開催ごとに大きく変わる場合に、開催内の多数派を標準として差を広げられる。案Bの試算・運用後に必要性を判断する。

たたき台の **S** は評価点の途中値。オッズの Seed プール **S**（[odds.md](odds.md)）とは別物。確定後は評価点側を別名にする。

## いま実装している式（正本）

未確定はここ1回だけ書く。以下はコードどおりの作者仮置き。Neko未確定。

土台は有効スキル数。緑は枚数に入れず、条件を満たすものだけステへ足す。ためらい4種はリスト外でも白1。金の +2 はためらいに載せない。**仮対策**: カタログ kind=`unique` / `evo` / `scenario`（キャラ固有・進化・シナリオ）は有効リスト外でも採用し、金と同じ +2。ただし緑マスタと名前が重なる進化は緑扱い（枚数に入れず金加算なし）。他の妨害は U-tools の無効判定に任せる。**戦略例外スキル**は U-tools 有効とは別レーン。D1 グローバルリストで id ごとに点数を持ち S0 に加算。例外に載っている id は U-tools 側には数えない（二重計上しない）。有効リスト未取得時は緑以外を全部有効とする。

補正の順: **生値 → 緑加算 → 適性S倍率 → r**。A は ×1。S だけ倍率。B 以下は減点しない。適性の正は [ウマ娘スクール ステータスと適性](https://umamusumeschool.com/status_aptitude/)。発動率の式には掛けない。「1200超は半減」は入れない。

| 節 | 適性S | N（達成） | M（未達） |
| --- | --- | --- | --- |
| スピード | 距離 ×1.1 | 4 | 見ない（r が 1 未満なら ×1） |
| スタミナ | なし | （離散） | 掛かりなし未達 ×0.4 / 掛かりありだけ未達 ×0.8。勝負コースは ×0.2 / ×0.4 |
| パワー | バ場 ×1.05 | 4 | 4 |
| 根性 | なし | 10 | 2 |
| 賢さ | 脚質 ×1.1 | 1（`S *= r`） | 6 |

スピードの要求は **継承の上限突破を入れないカンスト**。A が効くのは突破でそれを超えた分だけ。コミュニティではカンスト前提なので未達は見ない。起きたらデータ異常として直置き側で見る。

スタミナは他ステと違い倍率固定。両方達成は ×1（加点なし）。`0,4` は `0.4` の誤記として扱う。

```
S0 = 有効スキル数 + 2 × 金スキル数 + 戦略例外点数
// ためらい4種は白1。固有・進化は仮に金扱い（リスト外でも採用）。戦略例外は U-tools とは別レーン（二重計上しない）

r速 = (速 + 緑速) × (距離S ? 1.1 : 1) / 要求速
S *= r速≥1 ? 1+(r速−1)/4 : 1

スタミナ: 判定値 = スタ + 緑スタ。未達は ×0.4/×0.8（勝負コースは ×0.2/×0.4）

rパ = (パ + 緑パ) × (バ場S ? 1.05 : 1) / 要求パ
S *= max(0, rパ≥1 ? 1+(rパ−1)/4 : 1+(rパ−1)×4)

r根 = 根性 / 要求根
S *= max(0, r根≥1 ? 1+(r根−1)/10 : 1+(r根−1)×2)

r賢 = (賢 + 緑賢) × (脚質S ? 1.1 : 1) / 要求賢
S *= max(0, r賢≥1 ? 1+(r賢−1) : 1+(r賢−1)×6)
```

場内で比にして Seed にする（[odds.md](odds.md)）。

## 入力と保存

開催は `events.score_setup`（`EventScoreSetup` / `scoreSetup.ts`）。管理画面「レースイベント設定」。未設定なら直置きのみ。

開催設定を保存する際は、保存前に自動評価の出走馬について「現在値・再計算後・キャラスペック倍率」の変更一覧を表示する。確認してから保存・再計算を確定し、キャンセル時とプレビュー取得時には保存しない。出走一覧の「自動評価点を確認・再計算」も同じ変更一覧を使う。

再計算は出走登録中だけ実行できる。評価条件が未設定、または自動評価の出走馬に計算材料が不足している場合は、馬名を示して中止する。手入力評価の出走馬は再計算対象外。

- コース: U-tools 金ドット36（`score-courses.json`、`npm run extract:courses`）
- 天候・バ場・季節と要求値はレース単位の手打ち（頭ごとではない）
- 保存時に Worker が当該コース×4脚質の有効スキル id を U-tools から取り、`effectiveSkillIds` に固定する。白∩共通フィルタはしない。金も入れる。照合はスキル id。加えて通常の有効キャラページから `characterSpecs`（キャラ数、合計有効バ身数、固有／進化スキル別の有効バ身数）を取得し、中央値 `R` の算出に使う。sp-calc には無い
- 継承固有は kind=`inherit`（継承進化は `special`）。効果量差はまだ付けない。土台に入れるかは **有効リストにその id があるか**（リスト外は数えない。ためらいは例外）。表示・金判定の kind は **skill id 優先**（同名 unique と取り違えない）
- キャラ固有（`unique`）・進化（`evo`）・シナリオ（`scenario`）はリスト外でも採用し金同等（+2）。緑マスタと名前が重なる進化は緑枠（枚数・金加算なし、ステ加算は緑経路）。固有／進化の有効バ身数は `characterSpecs` と出走スキルIDを照合し、スキル点へキャラスペック倍率として反映する。
- 要求パ・根・賢の初期表示は速2150・パ1600・根1200・賢1600（`DEFAULT_SCORE_REQ`）。全コース表は作らない（シナリオで目標が変わる。メンテが割に合わない）
- 要求スタミナは脚質（逃げ・先行・差し・追込）ごとの掛かりなし／ありの8値。初期は空。スタミナ勝負の有無は開催フラグ。有志ツールの移植はしない

出走は `horses.score_input`（ステ・適性・スキル名・id・脚質）。`scoreFromHorse` → Strength。OCR の id 化は [ocr.md](ocr.md)。脚質の初期選択も同ファイル。U-tools キーは 逃=runner / 先=leader / 差=betweener / 追=chaser。

緑のマスタは `src/data/green-skills.json`。判定は `greenCondition.ts`（`@`=OR、`&`=AND）。開催条件＋頭の脚質で満たす緑だけ実数値に足す。人気・枠・抽選・同スキル頭数など手打ちに無いキーは不成立。OCR カタログの green（固有アイコン）とは別。枚数+1 は使わない。

直置きは算出不能時、または出走登録／編集で **評価点を直置き** pill を ON にしたときの逃げ。UI は pill トグル（`strength_manual`。チェックボックスは画面外）。OCR 読取確認では自動算出が既定で、pill で手入力 Strength に切り替える（[ocr.md](ocr.md)）。

## Neko案との対応

原文の訂正と、実装に載せた意味。式の再掲はしない。根拠は次節。

**原文の訂正**

- スピード・スタミナ節の「パワーの実数値に加算」→ その節のステへ足す
- 根性節の「要求パワー」→ 要求根性
- スタミナの `0,4` → `0.4`

**採用（実装どおり）**

- 金は有効に含めたうえで +2（通常1・金3）。Neko記事の「金は白3つ分に近い」と一致
- 無効スキルの表は使わない。正は U-tools 36コース×脚質
- 達成側は候補 A（超過分だけ 1/N）。未達は `1+(r−1)×M`
- スピード未達は書き漏れではなく起きない前提
- 適性は S だけ倍率。緑は条件成立時の内部上昇を実数値へ
- デバフの特別扱いはためらい4種だけ（白1）

## 読みの根拠（普段見ない）

実装の正本ではない。原文の口語を数式にした過程。

全体は一本の掛け算パイプライン。スキル数で土台を作り、5ステで倍率を順に掛ける。

### スキル数（土台）

1. スクショのスキルを列挙する
2. 今のレースで無効なものを落とす
3. 今の脚質で無効なものを落とす
4. 緑はスキル数に入れない（後でステ加算に回す）
5. ためらい4種は名前または id で拾い、有効 +1。他の妨害は無効リストに任せる
6. 残った有効スキルを数える
7. 金の枚数×2 を足す（ためらいは金カウントに入れない）

無効は「有効リストに無いものを落とす」。

### ステ共通の型

- 目標値は開催ごとに手入力（パ・根・賢、スタミナは脚質別の掛かりなし／あり8値。速は継承突破なしカンスト。スタミナ勝負は開催フラグ）
- 実数値はスクショの生値＋緑の内部上昇
- 補正: その節の適性Sならサイト倍率
- 達成比 `r = 補正後実数値 / 目標値`
- 達成時は S を r に応じて伸ばす。未達時はペナルティ（スピードは未達を見ない）

### 「実数値÷目標値÷４の値だけSを倍にする」

同じ型が4節ある。

| 節 | 原文の X | 直後 |
| --- | --- | --- |
| スピード | 実数値÷目標値÷４ | なし |
| パワー | 同じ | 「この値が1.0を下回るの場合…」 |
| 根性 | ÷１０ | 同じ「この値」 |
| 賢さ | 実数値÷目標値（÷なし） | 同じ「この値」 |

文法の芯は **「Xの値だけSを倍にする」**。÷４は X の一部で、「倍」は ×2 ではない。賢さに ÷４ が無いのに同じ「倍にする」があるので、「倍」= **倍率を掛ける** の口語。

`r = 実数値 / 目標値` と置く。

**「この値」は r であって r/4 ではない。** パワーで r/4 を 1.0 と比べると、実数値が目標の4倍未満なら常に未達側へ落ちる（ウマ娘では常時）。1.0 判定を書く意味が無い。だから ÷４ は達成側の加減だけ。未達は別文。

字面どおり `S *= r/4` は、目標ちょうど（r=1）で S が 1/4 になる。土台のスキル数を壊す。**字面は棄却。**

残りは、「賢さは r をそのまま倍率にする」を原型とし、スピード／パワー／根性はそれを **弱めた書き方** と見るか。

賢さを原型にすると、達成側の意図は `S *= r`（r=1 で据え置き、超過は比例）。弱め方の書き損じが ÷４。

| 候補 | 達成の式 | r=1 | r=1.2（2割超過） | 注記との相性 |
| --- | --- | --- | --- | --- |
| A | `S *= 1 + (r−1)/N` | ×1 | N=4 なら ×1.05 | 「達成メリット少ない」= 超過の効きを 1/N にする。÷N を **差（r−1）** に掛けた形。書きは r÷N になっている |
| A' | `S *= 1 + r/N` | N=4 なら ×1.25 | ×1.30 | 「の値だけ」を加算と読む。目標達成時点で既に +25%。メリット少ないとやや矛盾 |
| B | `S *= r`（÷N は無視） | ×1 | ×1.20 | 賢さと同一。÷４が死ぬ |
| C | `S *= r/N` | ×0.25 | ×0.30 | 棄却 |

**達成は A を採用。** 根拠は (1) 賢さ節が `S *= r` と読める (2) `1+(r−1)/1 = r` で賢さと同型 (3) ÷４／÷１０は超過の効きを薄くする係数 (4) 目標ちょうどで土台を壊さない (5) パワー注記と矛盾しない。

書きとの差: 本文は `r/4`、A は `(r−1)/4` を 1 に足す。**比そのものを割る**と **超過分だけを割る** の取り違え。口語の「÷４の値だけ」は後者。

### 「１－目標値を４倍」

未達側。目標が千点台だと字面は意味をなさない。達成 A と同じく、差は `r−1`（未達なら負）。

「１－目標値」→ `1−r` = `−(r−1)`。「をM倍」→ その差を M 倍。掛けるのは差そのものではなく、達成と同じ **1 に足す**。

`S *= max(0, 1 + (r−1)×M)`

`(r−1)×M` だけを倍率にすると r<1 で負になり S が壊れる。A の「同じく」は **差に係数を掛けて 1 に足す** の側。

検算: `1 + (r−1)×M = 1 − M(1−r)`。r=1 で達成・未達とも ×1。パワー M=4・1割不足（r=0.9）は ×0.6。r≤1−1/M で 0（パワーは 75% 未満で評価点 0）。

注記との対応:

- パワー: 達成メリット小・未達デメリット大 → N=4, M=4
- 根性: 未達は軽い → N=10, M=2
- 賢さ: 両方大きい → N=1, M=6
- スピード: 未達なし。要求は継承突破なしのカンスト。超過（突破分）だけ N=4

### 節ごとの補正の根拠

順は **生値 → 緑の内部上昇を加算 → 適性Sなら倍率**。緑は同じステの上昇。適性Sは「そのステの効き」。先に足してから倍率する方が、育成で盛った分と緑が同じ土俵になる。逆（適性→緑）だと、S馬の緑だけ倍率の外に出て薄い。サイトの体力式も「スタミナ＋緑」を括弧の中に置き、そのあと係数を掛けている。差は緑が大きいとき以外は小さい。

掛かり発生時の要求 ≥ 未発生の要求、が普通。両方未達は「未発生が未達」に含まれる、と読める。

## たたき台（原文）

■強さの根幹はスキル数

・１ スクショからスキルの数を数える。
・２ レースに応じた無効スキルを読み込む。
・３ 脚質に応じた無効スキルを確認する。
・４ 緑スキルを計算から除外する。
・５ 有効スキルの数をカウントする。
・６ 金スキルの数×２を有効スキルの数に追加し、スキル数を保存する。
⇒S

■要求スピードの確認

・１ 要求スピードを確認し、スクショから達成か未達を確認する。この際、距離Sか、スピードの緑スキルの数を確認し、パワーの実数値に加算する。
・２ 実数値÷目標値÷４の値だけSを倍にする。

■要求スタミナの確認

・１ レースと脚質に応じた掛かりは発生しない場合の要求スタミナと、掛かりが発生した場合の要求スタミナを確認する。
・２ スクショから要求スタミナがクリアされているかを確認する。この際、スタミナの緑スキルの数を確認し、パワーの実数値に加算する。
・３ 掛かり未発生の目標がクリアされていない場合、Sの値を0.4倍にする。掛かり発生時の目標のみクリアされていない場合、Sの値を0.8倍にする。もしもそのコースがスタミナ勝負のあるコースの場合、代わりに0.2倍と0,4倍にする。

■要求パワーの確認

・１ 要求パワーを確認し、スクショから達成か未達を確認する。この際、バ場Sか、パワーの緑スキルの数を確認し、パワーの実数値に加算する。
・２ 実数値÷目標値÷４の値だけSを倍にする。この値が1.0を下回るの場合、１－目標値を４倍にする。※パワーは目標を達成するメリットが少ないが、達成できないデメリットが大きいため

■要求根性の確認

・１ 要求パワーを確認し、スクショから達成か未達を確認する。
・２ 実数値÷目標値÷１０の値だけSを倍にする。この値が1.0を下回るの場合、１－目標値を２倍にする。※根性未達の影響は軽い。

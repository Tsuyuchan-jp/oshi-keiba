# OCR（本戦スクショ）

本戦出走のステータス画面などから、評価点の材料を読む。予選はアプリに載せないので、OCR も本戦のみ。

第2回の努力目標。間に合わなくても開催する。そのときは評価点を直置きする（[playbook.md](playbook.md)）。点の式は [score.md](score.md)。レース結果の動画・リプレイからの着順取得はしない（[rejected.md](rejected.md)）。

## 方針

入力は **スクリーンショット画像**。ゲーム内キャプチャや画像結合は当アプリではやらない。

流れ: **スクショ入力 → OCR → ステータスのテキスト化**（評価点の材料）。読めなかった頭は直置きと混在できること。

ベースはデスクトップアプリ **umamusume-skill-emulator** の OCR 遺産（Gemini で詳細ステータス画面を JSON 化）。当アプリ向けに切り出すものは読取とテキスト化まで。シミュレーション・オートキャプチャ・結合は持ち込まない。

遺産の参照先（ローカル）: `Documents/google antigravity/umamusume-skill-emulator`（特に `desktop-app/app/lib/geminiOcr.ts`・`fuzzyMatcher.ts`）。

## 実行場所（B）

管理者の **ブラウザが Gemini を直接叩く**。Workers に API キーも画像も送らない。

- キーは操作する人の端末（管理画面のこのブラウザ）に置く。リポジトリ・`wrangler` の vars・サーバ秘密には置かない
- 請求と無料枠はキーの Google アカウント。無料枠で金銭ゼロに寄せる。課金アカウントは紐づけない
- モデルは遺産と同じ `gemini-3.1-flash-lite`（画像読取。画像生成モデルではない）
- 出走登録の操作者は当面作者。Neko長明さんが触るときは **本人のキー** か、OCR なしの直置き。作者のキーは渡さない

## 管理画面（仮）

`/admin` の setup だけ。メンバー画面には出さない。

1 頭ずつスクショを選ぶ → 読取 → 名前・ステ・適正・スキルをテキストで見せて直せる → 既存の出走登録（名前＋評価点直置き）に載せる。キー未設定・失敗・未読取の頭は今どおり直置き。

画像はサーバに残さない。読取テキストの DB 保存は、評価点が直置きのあいだ必須にしない。

## 範囲（仮）

読むもの（たたき台が要求している入力。遺産の抽出項目と整合）:

- スキル一覧（数、金／緑、無効判定の材料）。**デバフも含む**
- ステ実数値（スピード・スタミナ・パワー・根性・賢さ）
- 適正（距離・バ場・脚質の S など）

### 遺産の穴（忘れない）

skill-emulator はシミュレーション用なので、**デバフ（minus）を取得スキルに載せない／umasim 未収録なら落とす**実装がある。当アプリの評価点はスキル数が根幹でデバフも材料になる。プロンプト・マッチ辞書・フィルタをそのままコピーしない。読取結果にデバフが残ること、金／緑／デバフが区別できることを後工程の条件にする。

出さないもの:

- メンバー画面への評価点・読取ログの露出
- 予選参加者の一括読取
- 着順の自動取得
- ライブキャプチャ・スクロール結合・レースシミュレーション
- サーバ経由の Gemini 呼び出し

失敗したらその頭だけ手直しできるようにする。全員分が読めなくても、読めた頭と直置きを混在して setup を終えられることを目標にする。

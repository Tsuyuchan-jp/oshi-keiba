# OCR（本戦スクショ）

本戦出走のステータス画面などから、評価点の材料を読む。予選はアプリに載せないので、OCR も本戦のみ。

第2回の努力目標。間に合わなくても開催する。そのときは評価点を直置きする（[playbook.md](playbook.md)）。点の式は [score.md](score.md)。レース結果の動画・リプレイからの着順取得はしない（[rejected.md](rejected.md)）。

## 方針

入力は **アプリ外で結合済みの完成スクショ1枚**。ゲーム内キャプチャや画像結合は当アプリではやらない。メンバー提出は umamusume-receipt-capture および有志のレシート因子メーカーを使う想定。

流れ: **完成画像を選ぶ → OCR → ステータスのテキスト化**（評価点の材料）。読めなかった頭は直置きと混在できること。

ベースはデスクトップアプリ **umamusume-skill-emulator** の OCR 遺産（Gemini で詳細ステータス画面を JSON 化）。当アプリ向けに切り出すものは読取とテキスト化まで。シミュレーション・オートキャプチャ・結合は持ち込まない。

遺産の参照先（ローカル）: `Documents/google antigravity/umamusume-skill-emulator`（特に `desktop-app/app/lib/geminiOcr.ts`・`fuzzyMatcher.ts`）。

## 実行場所（B）

**Gemini 呼び出し**は管理者のブラウザが直接行う。Workers に API キーは置かない・送らない。

- キーは操作する人の端末（管理画面のこのブラウザ）に置く。リポジトリ・`wrangler` の vars・サーバ秘密には置かない
- 請求と無料枠はキーの Google アカウント。無料枠で金銭ゼロに寄せる。課金アカウントは紐づけない
- モデルは遺産と同じ `gemini-3.1-flash-lite`（画像読取。画像生成モデルではない）
- 出走登録の操作者は当面作者。Neko長明さんが触るときは **本人のキー** か、OCR なしの直置き。作者のキーは渡さない

**保存用の画像**は Gemini とは別経路。本体は R2、D1 には参照だけ。キーは乗せず、画像ファイルだけ Worker へ送る。**表示 UI は後回し**（どこでどう見せるかは機能追加）。実装は未着手。

## 登録名

出走は **ウマ娘名** と **出走者** を分ける。OCR のキャラ名はウマ娘名へ流す。出走者は手入力。

メンバー画面の見せ方（1列に結合するか、列を分けるか）は未決。仮は今と同じ「ウマ娘（出走者）」1列。

## 管理画面（仮）

`/admin` の setup だけ。メンバー画面には評価点も読取ログも出さない。スクショそのものをメンバーに出すかは未決（管理者が見るのが先）。

1 頭ずつ完成画像を選ぶ → 読取 → ウマ娘名・ステ・適正・スキルをテキストで見せて直せる → ウマ娘名へ OCR を流し、出走者と評価点は手入力。キー未設定・失敗・未読取の頭は今どおり直置き。

評価点（Strength）は OCR では埋めない。

## 画像の置き場（検討）

1 枚おおよそ 800KB。本戦 18 頭なら 1 開催約 14MB。公開済み開催は残すので、開催を重ねると画像だけが増える。

**D1（いまの無料枠 DB）には画像本体を置かない。**

| 制約 | 無料枠の目安 | 800KB 画像 |
|---|---|---|
| 1 行（BLOB） | 最大 2MB | 1 枚は入る |
| 1 本の DB | 500MB | 画像だけなら三十数開催で上限付近。票・Undo と取り合う |
| SQL 文の長さ | 100KB | 文に画像を載せる経路は不可 |

読み書き回数の無料枠（1 日の行数）は、開催ごとの十数枚では問題にならない。足りないのは **容量と、画像向きでないこと**。

画像は **R2**（オブジェクトストレージ）が向き。D1 には頭 ID など参照だけ。R2 の無料枠はおおよそ **保存 10GB / 月**（Standard）。800KB なら数千枚、週1・18頭でも数年分は容量上足りる。書き込み・読み取り回数の無料枠もこの規模では余る。egress は R2 側は無料。この催しの規模では **無料枠で保存して問題ない**。

先にやるのは保存できること（R2 バケット、D1 の参照、アップロード）。管理画面やメンバー画面への表示は後の機能追加。

Workers のリクエストに 800KB を載せることは、このサイズでは問題にならない。

## 範囲（仮）

読むもの（たたき台が要求している入力。遺産の抽出項目と整合）:

- スキル一覧（数、金／緑、無効判定の材料）。**デバフも含む**
- ステ実数値（スピード・スタミナ・パワー・根性・賢さ）
- 適正（距離・バ場・脚質の S など）
- ウマ娘名（出走者は読まない）

### 遺産の穴（忘れない）

skill-emulator はシミュレーション用なので、**デバフ（minus）を取得スキルに載せない／umasim 未収録なら落とす**実装がある。当アプリの評価点はスキル数が根幹でデバフも材料になる。プロンプト・マッチ辞書・フィルタをそのままコピーしない。読取結果にデバフが残ること、金／緑／デバフが区別できることを後工程の条件にする。

出さないもの:

- メンバー画面への評価点・読取ログの露出
- 予選参加者の一括読取
- 着順の自動取得
- アプリ内のライブキャプチャ・スクロール結合・レースシミュレーション
- サーバ経由の Gemini 呼び出し

失敗したらその頭だけ手直しできるようにする。全員分が読めなくても、読めた頭と直置きを混在して setup を終えられることを目標にする。

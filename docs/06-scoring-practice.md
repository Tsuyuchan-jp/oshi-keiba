# 点数化の進め方（数学が前提にない場合）

この文書は「正しい式の導出」ではなく、**体感を、あとから直せる数字にする手順**である。統計の知識は必須にしない。

## 二層に分ける

| 層 | 今の要件①でやること | やらないこと |
|---|---|---|
| 構造 | 入力は何か、出力は何点の意味か、単調か（温存リスクは高いほど減点が増える） | 最適な曲線の種類を選ぶ |
| 数字 | 自分が説明できる **錨（アンカー）を 3〜5 個** 置く | 錨と錨の間を fancy な関数で埋める |

錨の間は、最初は折れ線（点と点を直線で結ぶ）で足りる。見た目が雑でも、論理は錨に全部入っている。滑らかさは後から足せる。

## 絶対点ではなく比較で置く

「温存 70% は何点か」を真空で決めない。次の言い方にする。

- 同じレースで、リスク 8% の馬と 16% の馬が並んだとき、**自分はどれくらい評価を下げるか**
- 「1 段落とす」を他モジュール何点相当にするかは、混ぜる段階まで持たない

モジュール比重（固有 3.5 / ステ 2.5 / スキル 4）がまだ仮なので、スタミナ単体の点をセンチ単位で詰めても、混ぜたあとで相対が崩れる。だから **今はスタミナモジュール内部の形だけ**決め、全体の何点分かは後で比重と一緒に触る。

## いま決めてよい粒度 / まだ早い粒度

**今（設計の言葉を固定する）**

- 入力の軸（例: 温存発生確率 0〜100%）
- 超過は加点しない、など既に決めた向き
- 錨 3 点くらいを言葉で置く（温存リスクは 0〜8% / 16% / 40% 超）
- 減点の入れ方（温存はスタミナ枠からの引き、に決定）
- スキルは個別点ではなく段・カテゴリ（固有 4 段、④は種類）

**まだ早い（実装の直前か、何頭か手で採点してから）**

- 指数関数かロジスティックか、といった曲線の種類
- 1% ごとの点数表
- 距離・脚質・バ場ごとの別曲線（入力の確率側に既に入っているなら、減点側で二重にやらない）

手で 3 頭だけ採点して「この順にならないのはおかしい」が言えるようになったら、錨の数字を動かす。それが学習の本体で、最初の式合わせではない。

## 温存まわりの到達点

1〜3 は 2026-08-18 時点で埋まった。このトピックは要件①としては一旦閉じ、点数のセンチや 16〜40% の中間は手採点のあとで触る。

1. 入力はツールの発生確率。距離・脚質・バ場・かかりはツール任せ
2. 減点はスタミナ枠のみ
3. 錨: 0〜8% 減点ゼロ、16% で 1 段、40% 超で大減点。低いほどよい

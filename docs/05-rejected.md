# 見送った案

再検討するときは、ここに書いた却下理由が今も成立するかだけ見る。

## GitHub Pages でデモをホストする

静的配信だけで共有の残高・投票を持てない。仮パスワードをフロントに置くと秘匿にならない。デモの公開は Cloudflare。Pages は見た目の静的プレビュー以外では使わない。

## 実ゲームのリプレイから実況・着順を取る

メモリ読み・パケットは規約的にグレー〜アウト。公式エクスポートもない。OCR/動画はコストに見合わない。採用しない。

## シミュ実況

umasim のログで実況する案は、作者のモチベーションに合わない。採用しない。

## ブックメーカー（固定オッズ）

運営が損失リスクと調整を負う。少人数イベントには向かない。パリミュチュエルを採用。

## 初期シードを Neko長明さんの3連単予想にする

実装は軽い。ただし投稿で「このアプリの本質」とされた **製作者がステとスキルから V を置く** を放棄する。Seed の本線にはしない。比較・答え合わせ用途には残しうる。

## A案: 単走 WASM タイムのリサンプリングで勝率 → Seed

- S: 1頭あたりの単走回数（タイムの袋）。現行アナライザーでは 1000 回で約 10〜15 秒
- M: 袋からタイムを引いて仮想着順を取る回数（軽い）

却下理由:

- 単走ではポジションキープで後方脚質が後ろを取らされ、同実力でも前脚質が秒単位で速い
- 脚質オフセットのダミー実測は、脚質専用スキルと発動条件が同時に変わるため「脚質だけの秒」が取れない
- リサンプリングは袋のバイアスを消さない
- 「正しい勝率」目標そのものが、検証手段不足で詰む

単走タイムを Seed の入力にしない。脚質をまたがない参考値としての再利用は、必須ではない。

## B案: 多頭 WASM 改修で Seed

①の前提にはしない。umasim 理解の学習目標としては将来ありうる。そのときは `Seed_i` の中身だけ差し替える。

## ツール側の「せーの」演出

note が既に予想・実況・結果提示を担う。独自カウントダウンは作らない。

## 投票中にゲーム飛び入りをアプリ名簿へ足す

飛び入りはルールで禁止。起きた場合のアプリ扱いは要検討（ゲーム内再出走が分かりやすい案）。投票中に名簿を足して Seed を組み直す本線にはしない。

## 実レース後〜予想 note 直前まで投票を開ける

現行儀式では note はレース後。ここまで開けると、ゲーム内ですでに着順を見た人（出走者・部屋管理者）が賭けられる。結果後投票になるので採用しない。締切は着順が見える前（ルーム出走に合わせる）。

## Strength 混ぜの A（基準表から絶対点）

各枠に 36 コース共通の基準を置き、加減点で1頭の点を出してから最後に相対化する案。

却下理由:

- サポカ編成・新シナリオで取得スキルポイントの絶対値が変わる。統一基準表を保てない
- 初期オッズに差が見えた方がエンタメとしてよい、という要求にも、場内で早めに相対化する B の方が合う

方式 B を本採用。比率 3:1 は後から触ってよい。

## 最終オッズと配当をずらす

締切後も Seed 込みを「最終オッズ」として出し、払い戻しだけ実点にする案。板は連続するが、競馬では確定オッズが配当なので、見た目が嘘になる。作者判断で大問題。却下。

投票中の Seed 込みは参考、確定オッズと配当は実点で一致、に切り替え。

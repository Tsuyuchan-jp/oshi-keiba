# プロダクト

## 何を作るか

推し活イベントレースに対し、仮想ポイントで馬券を買える閉じたツール。

中心体験は Neko長明さんの note（予想 → 実況 → 結果）と感想戦。ツールは儀式を置き換えず、賭けの部品を足す。アプリは **本戦** を回す。予選はアプリ外。

## 作者の役割

- 催し全体のプロデューサーではない
- Neko長明さんが回している儀式へのコントリビューター（開発者）
- コミュニティにはメンバーが自発的にツールを持ち込む前例がある（アイビーさんの試作）

催し全体の大確認はしない。動く板を見せたうえで、運用に直撃する箇所だけ聞く。

## ガードレール

Neko長明さんの掲示板回答に合わせる。

- 抽象論としてはゲーム規約・刑法の賭博規定に触れうる、という建前がある
- 運用: **外部に出さない**、**現物のやり取りを始めたらキック**
- 仮想ポイントに換金性を持たせない。賞品は転売可能な現物にしない（現行の1着賞品＝絵の進呈と地続き）

公開前にアイビーさんへ一言（先行して試作を出していたため）。

## 結果の扱い

- 着順は主催者（または委任）が手動入力して確定。ツールはレース結果を自動取得しない
- 「せーの」は note が担う。ツールはネタバレしないことが仕事
- 投票締切と、着順確定・清算は別。締切後に確定配当（倍率）は出してよい。勝ち馬・払戻は note 公開に合わせる

## 儀式とルームマッチ

儀式の流れは変えない。ツールは投票期間を足す。

ゲーム側:

- 部屋立てから出走まで最短 30 分〜最長 24 時間
- 管理者は待たずに登録を締め、強制出走できる
- 出走のあと、管理者も出走者もゲーム内で結果を見られる

推し大会の現行:

1. 前日（土曜）21 時ごろ部屋立て。出走まで 24 時間
2. 翌日、オートで登録締切・出走
3. その時点からゲーム内で結果が見える
4. 数時間後、note（予想 → スクショ付き実況 → 結果）。号外1枚は管理者が note 用に撮る。ウマ柱はレース前の話題用で、投票中は場内からメンバーも閲覧できる（[umabashira.md](features/umabashira.md)）。号外はメンバー画面には出さない（[gougai.md](features/gougai.md)）

### 馬券締切

上限（必須）: ゲーム内で着順が見えるより前。ルームの出走（24 時間オートまたは強制）に合わせる。

予想 note より前であることは、レースが先なので従属して満たす。実レース後・note 直前まで開ける案は採用しない。

アプリは **日時指定締切** と **強制締切ボタン** の両方。ボタンはゲーム内で結果が出るより前に押す。

### 週次（仮置き）

締切は種類が違う。同じ「締切」と呼ばない。投票開始と部屋立ての前後は未決。仮置きの並びは投票のあとに部屋。

1. レギュ確定と、出走登録（スクショ）締切の明示
2. 出走者は締切までに育成を終え、ステータス画面のスクショを提出
3. 本戦名簿をアプリに載せる。登録はウマ娘名と出走者を分ける（メンバー画面は列を分ける・仮）。評価点（OCR または直置き）と参考オッズ。スクショはアプリ外で結合した1枚。メンバーには今出さない（[ocr.md](specifications/ocr.md)）
4. 馬券の投票期間
5. 馬券締切（着順が見える前。日時＋強制ボタン）
6. 事前登録者だけがゲーム内部屋で出走
7. note。公開タイミングに合わせて着順確定と払戻

### 飛び入りと取消

- 飛び入りはルールで禁止（事前提出者以外はゲーム部屋に乗らない）
- 事前登録あり・ゲーム内なし: そのウマ娘への投票を全額返還
- 事前なし・ゲーム内に乗った場合: 要検討。分かりやすい案はゲーム内だけ再部屋・再出走（アプリの名簿は確定のまま）

## ポイント

仮想資産。週をまたいで貯められる。開催は1本ずつ進め、公開済みは残す。新しい開催では、投票中に参加した人へ G を1回足す。来なかった人には配らない。1頭へ所持全額を載せてよい。1人一票にしない。換金しない。画面の単位名は **スペ**。

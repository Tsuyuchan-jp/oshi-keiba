# プロダクト方針

## 何を作るか

推し活イベントレースに対し、仮想ポイントで馬券を買える閉じたツール。

既存の中心体験は Neko長明さんの note（予想 → 実況 → 結果）と、その後の感想戦である。ツールは儀式を置き換えず、**賭け要素の部品**を足す。

## 作者の役割

- 催し全体のプロデューサーではない
- Neko長明さんが回している儀式へのコントリビューター
- コミュニティにはメンバーが自発的にツールを持ち込む前例がある（アイビーさんの試作）

Neko長明さんは「人に期待しない」方針があるため、事前の大確認より完成物ベースの軽い提示が、関係性として自然、という判断。

## ガードレール

Neko長明さんの掲示板回答に合わせる。

- 抽象論としてはゲーム規約・刑法の賭博規定に触れうる、という建前がある
- 運用ライン: **外部に出さない**、**現物のやり取りを始めたらキック**
- 仮想ポイントに換金性を持たせない。賞品は転売可能な現物にしない（現行の1着賞品＝絵の進呈と地続き）

## 結果の扱い

- 着順は主催者（または委任された人）が手動入力して確定
- 動画解析やゲームクライアントからの自動取得は MVP に入れない
- 「せーの」で結果を見る演出は note が既に担う。ツールはネタバレしないことが仕事
- 投票締切と、着順確定・清算は別イベント。締切後に確定配当（払う倍率）は出してよい。勝ち馬・払戻は note 公開に合わせる

## 既存儀式とルームマッチ（仮置き採用 2026-08-21）

儀式の流れは変えない。ツールは投票期間を足すだけ。

ゲーム側（ウマ娘のルームマッチ）:

- 誰でも部屋を立てられ、レギュレーションも自由
- 部屋立てから出走まで最短 30 分〜最長 24 時間
- 部屋の管理者は、この時間を待たずに出走登録を締め、強制出走できる
- 出走処理のあと、管理者も出走者もゲーム内で結果を見られる

Neko長明さんの推し大会の現行:

1. 前日（土曜）21 時ごろ部屋立て。出走まで 24 時間
2. 翌日、24 時間経過でゲームが登録締切・出走をオート実行
3. その時点からゲーム内で結果を見られる
4. 数時間後、note に予想 → スクショ付き実況 → 結果（結果を見る前の予想、という儀式）

### 投票締切

上限（必須）: ゲーム内で着順が見えるより前。本線はルームの出走（24 時間オートまたは強制）に合わせる。

予想 note より前であることは、レースが先なので従属して満たす。note は締切の理由ではなく、着順公開・清算を揃える相手。実レース後・note 直前まで投票を開ける案は採用しない（ゲーム内ですでに着順を見た人が賭けられる）。

アプリ側の手段（両方）:

- **日時指定締切**: 予定どおり 24 時間オート出走する週の本線。部屋立てが土曜 21 時なら、締切も翌日同時刻付近
- **ボタンによる強制締切**: ゲーム側の強制出走・前倒しに追従する。押すのはゲーム内で結果が出るより前

土曜 21 時〜日曜 21 時のゲーム登録期間にアプリ投票を開けてよい。事前登録と実出走のズレが縮む。部屋立てと同時に締める必要はない。

## 自走の範囲

完成時に 140 コースすべてで初期シードが自動確定する必要はない。本線（36 コースのバ身 + 温存ツール + ステ）は人手なしで回し、例外週だけ作者が代替を入れる。着順確定がもともと手動であるのと同じ種類の「オペレータが週に一度触る」設計。

Neko長明さんへは、初期シードの本線は U-tools バ身がある 36 コース内、と使用条件として伝えてよい。日曜推しレースで 36 外はこれまで 1 回。その場合の代替（近傍バ身、またはその週だけの段評価）は用意する。

## 最小フロー

1. 出走ウマ娘をツールに事前登録（ステ画面画像など。ゲーム内登録より前でも可）
2. 部屋立て後〜出走前までポイントを賭ける（日時締切、または強制ボタン）
3. 実レース（ゲーム内。オート 24h または強制）
4. 投票はすでに閉じている。確定配当は出してよい。着順は出さない
5. note 公開タイミングに合わせて主催者が着順確定
6. パリミュチュエルで清算

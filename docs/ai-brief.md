## 1. 何であるか

ウマ娘メンバーシップ（主催: Neko長明さん）の**推し活イベントレース**向け、**閉じた仮想馬券ツール**。

- 通貨は仮想ポイント。画面上の単位名は **スペ**。換金しない。現物のやり取りを始めたらキック、という運用がある。
- 中心体験は主催者の **note**（予想 → 実況 → 結果）と感想戦。本アプリは儀式を置き換えない。**賭けの部品だけ足す**。
- アプリが回すのは **本戦のみ**。予選はアプリ外。予選通過者の名簿だけ載せる。
- 作者の役割は催し全体のプロデューサーではない。既存儀式へのコントリビューター（開発者）。コミュニティにはメンバーが自発的にツールを持ち込む前例がある。

本番: `https://oshi-keiba.tsuyuchan-jp.workers.dev/`  
閉じた経路で URL を渡す。検索に出さない。GitHub Pages ではホストしない。

## 2. 絶対に守る制約

1. **仮想ポイントのみ。** 換金性・転売可能な景品は持たせない。現行の1着賞品（絵の進呈）と地続き。
2. **メンバーシップ外に出さない。**
3. **着順はゲーム／note より先にアプリが漏らさない。** ゲーム内で着順が見えるより前に投票を締切る。着順は主催者（または委任）が手動入力。リプレイ・動画・メモリ読みからの自動取得はしない。
4. **「せーの」は note が担う。** アプリ側の独自カウントダウンは作らない。
5. **払いの約束は実票だけ（方針 ①）。** Seed（評価点から作る仮想初期票）では払わない。投票中の Seed 込みは「参考オッズ」。締切後の実票パリミュチュエルが「確定配当」。見た目の嘘（参考を最終オッズとして出す）は却下済み。
6. **当選キーは賭式あたり常に1つ。** 複勝・ワイドは当たりが複数なので後回し。
7. **開催は1本ずつカレント。** 同時に投票できる開催は1つ。公開済み開催と口座残高は残して持ち越す。開催ごとに DB を初期化する本線は捨てた。

## 3. ゲーム／催しの時間軸（アプリが従うもの）

ゲーム側: 部屋立てから出走まで最短約30分〜最長24時間。管理者は待たずに登録を締め、強制出走できる。出走後、ゲーム内で結果が見える。

推し大会の現行（概略）:

1. 前日（土曜）21時ごろ部屋立て。出走まで24時間。
2. 翌日オートで登録締切・出走。この時点からゲーム内で着順が見える。
3. 数時間後、note（予想・スクショ付き実況・結果）。

馬券締切の上限（必須）: **ゲーム内で着順が見えるより前。** 実レース後〜note直前まで開ける案は却下。

週次の仮置き並び（投票のあとに部屋。前後は未決）:

1. レギュ確定と出走登録（スクショ）締切
2. 出走者は育成を終えステータス画面スクショを提出
3. 本戦名簿をアプリへ。評価点（OCR または直置き）
4. 馬券の投票期間
5. 馬券締切（日時＋強制ボタン）
6. 事前登録者だけがゲーム内部屋で出走
7. note 公開に合わせて着順入力と払戻

飛び入りはルールで禁止。投票中に名簿を足して Seed を組み直す本線にはしない。事前登録あり・ゲーム内なしは、そのウマ娘への票を全額返還。事前なし・ゲーム内に乗った場合のアプリ扱いは未決（ゲーム内再部屋が有力）。

## 4. 技術スタック（現状）

- Cloudflare **Workers**（TypeScript、SSR HTML。フロントの SPA フレームワークは使わない）
- **D1**（SQLite）: 開催・出走・会員・票・Undo・評価点材料・戦略例外
- **R2**: OCR 成功時の出走スクショ（バケット `oshi-keiba-shots`、キー `{eventId}/{horseId}`）
- Cookie セッション（共有パス入場。個人パスワードなし）
- 静的アセット: `public/`（場内背景イラストなど）
- テスト: Node 組み込み test。`npm test`（odds / lifecycle / score / storeFlow など）
- 版: `package.json` の `version` を画面に `v` 付き表示（`src/lib/version.ts`）

ローカル: `npm run dev:setup` → `npm run dev`（`http://localhost:8787`）。デモ初期化と Undo は `npm run dev` の `--var`（`ALLOW_DEMO_RESET=1` / `ALLOW_ADMIN_UNDO=1`）。`.dev.vars` は `secrets.required` のため認証4項目だけ。本番の vars は 0。

主要コード入口: `src/index.ts`。store は Types / Read / Board / Members / Horses / Event / Race に分割し `store.ts` が barrel。公開 API は不変方針。

## 6. 開催ライフサイクル

状態: `setup` → `voting` → `closed` → `published`。その後「次の開催を開く」で新しい `setup`。前の開催は残る。

| 状態 | メンバー向け文言 | 場内 | 窓口 |
|---|---|---|---|
| setup | 出走登録中 | 電光。買うなし。「投票開始までお待ちください」。入場は可 | 参加ボタンなし |
| voting | 投票中 | 変動あり。橙の「馬券を買う」。着列なし。ライブ5秒 | 未参加なら参加のみ。参加後は買う。参加で G が1回 |
| closed | 投票締切（確定配当） | 確定配当。着順は出さない。買うなし。賭式ごとの成立／特払い予定 | 買うなし |
| published | 結果公開 | 最初は払戻盤（左）＋縦長確定盤（右: ローマ数字・大きな通し番号・1〜5着。タイムは雰囲気用）。スワイプ／タップ／「全頭」で全頭表＋自分の馬券。着差は出さない（入力しない） | 自分の的中／特払い／取消 |

締切: **日時指定**と**強制締切ボタン**。締切日時は開始ボタンと別フォーム。保存してから開始（過去日時だと開始直後に自動締切）。着順保存のあと公開で払戻適用。

管理の危険操作（いずれもモーダルで管理者パス＋確認）: 開催破棄、出走クリア、投票を取り消して登録に戻す（票全額戻し、その開催の G も戻す）、Undo。投票開始後は Undo・メンバー削除を普段押さない。「次の開催を開く」は結果公開のあと。

頭数: **2〜18**。番号は出走登録タブで編集するウマ番（1〜出走頭数、重複なし。ゲームの枠番ではない）。開始後の取消は避ける。出走取消は、そのウマ娘を含む票の**全額返還**（特払いではない）。

## 7. 入場・ポイント・投票

- 初めて: 未登録なら口座作成。同名ありは拒否。この時点では G は入らない。
- 再入場: 既存なら入場。名前なしは拒否。表示名は空白のみ不可。絵文字可。Cookie があれば再入力不要。投票期間外の入場は可。
- **G**: その開催の投票中に `/bet` で初めて参加した人へ1回。来ない人には配らない。入場だけでは配らない。週をまたいで残高は貯まる。1頭へ所持全額を載せてよい。1人一票にしない。
- 第2回仮置き G=**3000** スペ、単位 **100** スペ（第1回と同じ G）。
- 締切前のやりなおし: 自分の票の**全取消**（確認文あり）。板が揺れるのは許容リスク。
- 1点買いのみ。ボックス・流しは今出さない。セレクトは使わずマークカード（チップタップ。枠ウェルで解除）。
- 馬連・3連複は順不同（内部ソート）。金額は単位どおり。`+100 / +500 / +1,000 / 全額を入力 / リセット`。下ドックの「買う」は押せる状態にし、不足している買い目・金額・残高を案内してから確認へ進む。
- 自分の票だけ見える。誰が何に賭けたか一般公開しない。コメントなし。

賭式（setup 中だけオンオフ可。単勝は必須。初期は全部オン）:

- 単勝 `win`
- 馬連 `umaren`
- 馬単 `umatan`
- 3連複 `sanrenpuku`
- 3連単 `sanrentan`

各賭式は別プール。

ライブ（voting のみ）: 5秒。裏なら止める。差が 0.1 倍以上の行だけ黄パルス。連勝は「—」から数字になった行を1回。買い目と金額は保持。トーストなし。

## 8. オッズ（払いの約束）

パリミュチュエル。Neko 投稿の骨格:

`オッズ = (総投票額 TV × (1 − 控除率 D)) / (その馬への投票額 V)`

D の目安 20%（管理では 0〜0.99。％UI にはしない）。少人数で板が荒いので Seed が要る。Seed の入力は評価点。Neko の 3連単予想は Seed にしない。WASM タイム→勝率も Seed にしない。ブックメーカー（固定オッズ）は却下。

**投票中・単勝参考（第2回・案 B）:**

連勝実票を単勝参考の TV と Display に乗せる（確定には入れない）。均一 Display フロア F は使わない。λ=1（管理画面では触らない）。連勝への Seed は出さない。連勝の表は実票がある組み合わせだけ（空は「—」）。

```
TV = 単勝実票合計 + λ × 連勝実票合計
w時 = 下限 + (1 − 下限) × 残り^指数
w票 = max(0, 1 − TV / E)
w = w時 × w票
Seed_i = S × 評価点_i / Σ 評価点
Display_i = Seed_i × w + 単勝Real_i + Imputed_i
参考オッズ_i = (Σ Display × (1 − D)) / Display_i
```

連勝額の割り振り例（λ=1・額600）: 馬連 300+300 / 馬単 400+200 / 3連複 各200 / 3連単 300+200+100。

第2回仮置き: S=80000, E=100000, w時下限=0.8, w時指数=1, λ=1, D=20%。G と S・E は独立。

開場直後の単勝倍率は評価点の比だけで、S の大きさでは変わらない。S は実票が混ざったあとの評価並びの重さ。

**確定:**

```
払戻しの原資 = その賭式の実票合計 × (1 − D)
確定配当 = 払戻しの原資 / 当たりの実票
払戻 = floor(賭け額 × 確定配当)
```

当たり実票ゼロ → **特払い B**: その賭式に賭けた全員へ控除後を戻す（100→80、端数切り捨て）。全額返還ではない。使い方文面に特払い段落は必須。履歴表記「特払い（8割戻し）」。キャリーオーバーをコミュニティ向けに出すかは未決。特払い率の変更は今は想定外。

内部記号（メンバーには出さない）: 評価点 / Seed / S / Real / Imputed / TV / w / E / Display / D / G。管理画面の項目名が Strength のままのことがある。

## 9. 評価点（Seed の入力）

ゴールは検定可能な真の勝率ではない。Neko が置いた強さの論理を、あとから直せる数字にする。作者独自のバ身混ぜ（旧 Strength）は使わない。

**実装はクローズ。** 自動算出 → Strength → Seed。材料不足・算出不能は直置き pill。式は作者側の読みで、**Neko 未確定**。確認したら `docs/score.md` を書き直す。たたき台の途中値 S はオッズの Seed プール S とは別物。

概略（詳細は score.md）:

- 土台は有効スキル数。緑は枚数に入れず、条件を満たすものだけステへ足す。
- 金は +2。ためらい4種はリスト外でも白1。金の +2 はためらいに載せない。
- 仮対策: カタログ kind=`unique`/`evo`/`scenario` は有効リスト外でも採用し金と同じ +2。緑マスタと名前が重なる進化は緑扱い。
- 戦略例外スキル: D1 グローバル。id ごとに点数を S0 に加算。U-tools 側には数えない（二重計上しない）。
- 有効リスト未取得時は緑以外を全部有効。
- 補正順: 生値 → 緑加算 → 適性S倍率 → r。A は ×1。S だけ倍率。B 以下は減点しない。「1200超は半減」は入れない。
- 開催条件は `events.score_setup`。コースは U-tools 金ドット36。天候・バ場・季節と要求値はレース単位の手打ち。保存時にコース×4脚質の有効スキル id をスナップショット。
- 出走は `horses.score_input`。脚質は人選択（逃/先/差/追）。OCR で脚質適性 S が1つだけなら初期選択。
- スタミナ要求値は脚質（逃げ・先行・差し・追込）×掛かりなし／ありの8項目を開催設定で入力・保存する。スタミナ勝負の有無も開催設定で保持する。

次の作業候補: コース別の固有／進化有効度を取り込み、仮の unique/evo＝金扱いを外す。

## 10. OCR（本戦スクショ）

機能クローズ。予選は対象外。着順取得 OCR とは別件。

- 入力はアプリ外で結合済みの完成スクショ1枚。ゲーム内キャプチャや結合は当アプリではやらない。
- Gemini 呼び出しは**管理者ブラウザが直接**。Workers に API キーは置かない。キーは端末 local。モデル `gemini-3.1-flash-lite`。無料枠。作者のキーは渡さない。
- 読取成功画像は R2 へ。メンバーには出さない（後ほど出す余地はある）。
- 登録は1頭ずつ。ウマ娘名（OCR）と出走者（手入力）を分ける。
- スキルはカタログへファジー照合して id 化。受け入れ MIME: PNG / JPEG / WebP。最大約 2MB。
- 読めない頭は直置き（スクショなし）と混在可。一括貼り付け枠なし。
- Gemini 精度改善そのものは作業キューに載せない。

## 12. 許容しているリスク（仕様）

- 表示名を知っていれば他人の口座に入れる
- やりなおしで板が揺れる
- 連勝は票が薄く、高配当か特払いになりやすい

## 13. 用語（メンバー向け vs 内部）

| メンバー | 内部・管理 |
|---|---|
| スペ | ポイント、balance |
| オッズ | 投票中は参考オッズ、締切後は確定配当 |
| 場内 / パドック / 窓口 / 入場 | `/` `/paddock` `/bet` `/login` |
| ウマ娘名 / 出走者 | uma_name / runner_name |
| （出さない） | 評価点、Strength、Seed、D、S、E、w、TV、Imputed |

フェーズ文言は上表（setup / voting / closed / published）を使う。同じ「締切」で投票締切とスクショ提出締切とゲーム登録締切を混ぜない。

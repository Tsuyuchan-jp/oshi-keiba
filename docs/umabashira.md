# ウマ柱（競馬新聞風）

管理者が生成し、コミュニティ内へ配る出走全頭の縦1列紙面。号外（[gougai.md](gougai.md)）とは別物。アプリのメンバー画面（場内・パドック・窓口）には埋め込まない。配るのは書き出した画像。

**いまの段階:** 実装可能。用途・評価点・印は確定。レイアウトの正はまだ無い。

---

## 可否

**実装できる。** 新しい勝率計算は不要。既に D1 にある開催・出走・評価点材料と、算出済みの評価点／参考オッズを並べて HTML にし、プレビューと PNG にする作業。号外と同じ配送路（管理タブ・モック先行・クライアント書き出し）。

ただし添付の実紙馬柱の複製にはならない。実紙の下半分は過去走5〜6走で、アプリにはそのデータが無い。できるのは「本戦1走分の材料を、馬柱の読み方に寄せて1枚に畳む」こと。

| 論点 | 判断 |
|---|---|
| データ不足で止まるか | 止まらない。識別・脚質・5ステ・適性・スキル・コース条件は揃う |
| 新規計算が要るか | 要らない。既存の `scoreFromHorse` / ボードの参考オッズを読むだけ。印も評価点の順位 |
| 頭数 2〜18 | 列数可変。実紙の16頭固定とは違う。モックで幅を試す |
| 枠番色 | アプリはウマ番のみ。枠番は扱わない（[playbook.md](playbook.md)） |
| 直置き頭 | `score_input` が無いとステ／スキル列が空。評価点と印は出る |
| 号外との干渉 | 管理タブ追加と PNG 手段だけ共有。紙面は別 |

---

## 進め方

号外と同じ順。いまは 2。

1. データ洗い出しと掲載案（このファイル。用途・出す項目は確定）
2. **レイアウト仮決め** … 添付馬柱を骨格にし、無いブロックはアプリ項目へ読み替え
3. HTML モック … `docs/mocks/umabashira/` で案を並べて比較（評価点とオッズの並びもここで見る）
4. 管理タブ … 差し込み・プレビュー・PNG。サーバー焼きは最初はしない（号外と同じ）

---

## 目的と置き場所

- いま: レース前の話題作り。コミュニティ内メンバーが見る画像を管理者が生成する。
- 生成: 管理者のみ。管理画面に生成専用タブ（例: `/admin/umabashira`、ラベル「ウマ柱」）。号外タブとは別。
- 配布: note 等へ貼る。アプリ内のメンバー画面には出さない（号外と同じ）。
- いつ: タブは開催の最初から出してよい。列が埋まるのは出走登録が進んだ時点。投票開始前はオッズ欄が空。印と評価点は登録が揃えば出る。
- 出さない: 場内・パドック・窓口への埋め込み、自動ポップアップ。

評価点はメンバー向け UI には出さない（[playbook.md](playbook.md)）。ウマ柱画像だけ例外で載せる。Seed・控除・誰が何を買ったかは画像にも出さない。

### 将来のファンツール（見越し。今は実装しない）

ウマ娘登録 → 評価点算出 → ウマ柱画像、だけを抜き出して、有志イベントの応援補助として公開する想定。

- 出す: 登録、評価点、ウマ柱
- **出さない: 勝ち馬投票に関する機能すべて**（口座、スペ、馬券、台帳、パリミュチュエル、確定配当）
- ファンツール側のウマ柱は、評価点と印だけで足りる。オッズ列は空になるか、列ごと無くなる

抜き出しはかなり先。今の紙面は「投票ありの本アプリ」向けに評価点とオッズを並べ、モックで比較する。

| 右端の凡例 | 印の意味など | モックで要否 |

## 人気印（確定）

競馬新聞の印は **人気（賭けられた額の順位）ではない。** 記者が「この馬が勝ちやすい」と付けた印。公式の計算法は無い。

| 印 | 呼び | 意味 |
|---|---|---|
| ◎ | 本命 | 紙面いちばんの推し |
| ○ | 対抗 | 本命に勝てる相手 |
| ▲ | 単穴 | 穴寄りだが勝ちも見る |
| △ | 穴 | 人気薄。複数頭につくことが多い |
| （無印） | | 印なし |

別物が **人気順**（1番人気、2番人気…）。単勝オッズが低いほど人気。印と人気がずれるのが新聞の話題になる。

このアプリでは印を評価点の高い順に機械で付ける。新しい確率は計算しない。オッズは市場側として別欄に出す。投票開始前は Seed 由来の参考オッズなので、印の順とオッズの順はほぼ同じ。投票が入るとズレうる。ファンツール（投票なし）では印だけが残る。

### 付け方

取消を除き、評価点 `strength` の高い順。同点はウマ番の小さい方を上。

| 順位 | 印 | 条件 |
|---|---|---|
| 1 | ◎ | 1頭以上 |
| 2 | ○ | 2頭以上 |
| 3 | ▲ | 3頭以上 |
| 4〜6 | △ | その順位の頭がいるとき |
| 7位以下 | 無印 | |

2頭立ては ◎○ だけ。3頭は ◎○▲。△ は最大3つ。◎○▲ は各1頭。

## 参照できるデータ

計算し直さず読めるもの。ソースは型と画面の正。

### 開催（`events` / `score_setup`）

| 項目 | 出所 | 備考 |
|---|---|---|
| 開催名 | `EventRow.title` | |
| フェーズ | `status` | setup / voting / closed / published |
| コース場・芝ダ・距離 | `getScoreCourse` | 例: 東京・芝・2400 |
| 天候・馬場・季節 | `conditions` | 晴／良／春 など |
| スタミナ勝負フラグ | `requirements.staminaRace` | 紙面に出す必要は薄い |
| ステ目標値 | `requirements`（脚質別スタミナ含む） | パドック詳細と同じ |
| 有効スキル id・キャラスペック | 保存時スナップショット | 内訳表示用。紙面向きではない |
| 頭数 | 取消以外の出走数 | 2〜18 |
| 締切時刻 | `voting_closes_at` | ヘッダに出すなら可 |
| 賭式・G・S・E・D | `EventRow` | **紙面に出さない** |

### 出走1頭（`horses`）

| 項目 | 出所 | 備考 |
|---|---|---|
| ウマ番 | `HorseBoard.number`（`sort_order`） | 1〜頭数。枠番ではない |
| ウマ娘名 | `uma_name` | |
| 出走者名 | `runner_name` | |
| 衣装 | `chara_id` / `dress_id` → カタログ | petit があれば名前は出さない |
| 取消 | `scratched` | 列から外す |
| 着順 | `finish_place` | 予想紙には出さない |
| 評価点 | `strength` | 直置きも同じ列。印の入力 |
| 材料の経路 | `seed_source` | 紙面に出さない |
| 意気込み | `paddock_comment` | 紙面へは入れない（パドックのまま） |
| 育成スクショ | R2 `shot_key` | 紙面に焼き込まない |
| トレーナーアイコン | R2 `trainer_icon_key` | 第1段は出さない（列が狭い） |

### 評価点材料（`score_input`。OCR または手入力）

直置きだけで材料が無い頭は、ここが空。

| 項目 | 内容 |
|---|---|
| 5ステ | 速・スタ・パ・根・賢 |
| 適性10 | 芝ダ・短マイル中長・逃先差追 |
| 出走脚質 | 逃／先／差／追 |
| スキル名と id | 有効・金相当・緑・戦略例外・不採用に分けられる |
| 不採用スキル | OCR が落とした名前。紙面に出さない |

コースに効く適性3つ（バ場・距離・脚質）は `scoreFromHorse` が既に拾っている。パドック詳細と同じ。

### 算出済み（新規式なし）

| 項目 | 出所 | 備考 |
|---|---|---|
| 印 | 評価点の順位 | 上の付け方 |
| 評価点の内訳 | `ScoreBreakdown` | 紙面は評価点の数字まで。式は出さない |
| スキルパワー | `breakdown.skill.base`（S0） | 有効／金の枚数と一緒に小さく出す |
| 有効／金相当／戦略点数 | 同 `skill` | |
| 成立した緑 | `appliedGreens` | スキル名側で分かる。独立欄は置かない |
| 単勝参考オッズ | `HorseBoard.referenceOdds` | 投票開始後。評価点と並べて比較 |
| 確定配当 | `confirmedOdds` | 予想紙には出さない |
| Seed / Display / 実票 | ボード | **紙面に出さない** |

集約の既存入口: `paddockView` と出走タブの内訳（`pipeHtml`）。ウマ柱用に計算を足さない。印は評価点のソートだけ。

### 画像

| 種類 | 解決 | 備考 |
|---|---|---|
| デフォルメ petit | `resolvePetitImageUrl` | `_0010`。パドックと同じ |
| 立ち絵 stand | 号外側の課題。ウマ柱第1段では使わない | |
| 育成スクショ | 管理 `/admin/shot/…` | 紙面には載せない |

血統・性齢・毛色・馬体重・騎手成績・調教タイム・過去走の着順／タイムは、参照できない。予選結果もアプリ外。

## 掲載（確定）

### 出す

- ヘッダ: 開催名、場・芝ダ・距離、天候・馬場、頭数
- 各列: 印、ウマ番、脚質、ウマ娘名、出走者、petit、評価点、5ステ、今走の適性3、スキル名（有効を優先。金／固有が分かる印）、有効／金の枚数
- 投票開始後: 単勝参考オッズ（評価点の隣。モックで並びを比較）

### 出さない

- 枠番色、血統、性齢、毛色、馬体重、騎手／調教師成績、過去走、調教タイム、日付、意気込み、衣装名、トレーナーアイコン
- Seed、Display、控除 D、誰が何を買ったか、着順、確定配当、評価点の式
- 育成スクショの焼き込み
- 勝率・シミュレーション・新しい指数
- 人気順の数字（1番人気…）。市場はオッズ欄だけ。印は評価点側

## レイアウトの仮（次の段で詰める）

骨格だけ。数値・フォントはモックで決める。

- 向き: 横長1枚。列 = 出走1頭。CSS Grid で列数 = 頭数
- 上: 開催ヘッダ（実紙の左上）
- 各列 上→下: 印＋ウマ番＋脚質 → 名前＋petit → 出走者 → 評価点とオッズ → ステ＋適性 → スキル
- 実紙の「過去走ブロック」は置かない。同じ高さをスキルリストに使う
- 18頭でも読める最小字をモックで確認する。スマホ幅に収めない（号外の 26rem とは違う）
- モックでは評価点／オッズ／印の位置を2案以上置いて比較する

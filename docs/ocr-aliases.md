# OCR 例外対応リスト（スキル名）

Gemini が返したスキル名が、カタログ正式名とずれたときに **手で足す対応表**。正規化（空白除去・全角英数→半角など）のあと、この表で完全一致した文字列だけ正式名に差し替えてからファジー照合する。

正本はコード: `src/lib/skillFuzzy.ts` の `OCR_SKILL_ALIASES`。ブラウザ側の読取確認も同じ表（`ocrAdmin.ts` の `ALIAS`）。**片方だけ直さない。** Docs を直したらコードも揃える（または逆）。

ファジー（編集距離≤1・Dice≥0.45）で拾えるものはここに載せない。**OCR落ちに出た生文字列**をコピーして足す。

## いまの対応

| OCR 側（落ちた／誤読しやすい表記） | カタログ正式名 | メモ |
|---|---|---|
| 千銀万錬 | 千鍛万錬 | 銀↔鍛 |
| 千段万錬 | 千鍛万錬 | 段↔鍛 |
| 千錬万錬 | 千鍛万錬 | 錬↔鍛。編集距離1でも拾えるが念のため |
| 勝利へ至る累積 | 勝利ヘ至ル累積 | へ／至る（ひらがな）↔ ヘ／至ル。2文字差でファジー落ち。実機確認済み |

## 足し方

1. 読取確認の **OCR落ち** バッジから文字列をコピーする（目視のひらがな／カタカナは当てにしない）
2. `skill-catalog.json` の正式名を確認する
3. 上の表と `OCR_SKILL_ALIASES` / `ALIAS` に同じ行を足す
4. `skillFuzzy.test.ts` に1本足す（先頭／2番目以降で unique／inherit が分かれるものは両方）
5. このファイルの表を更新する

関連: [ocr.md](ocr.md)（読取の流れ）・[score.md](score.md)（評価点）。戦略例外スキル（点数の別レーン）はここではなく D1／管理モーダル。
